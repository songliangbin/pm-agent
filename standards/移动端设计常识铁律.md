# 移动端设计常识铁律（14 条）

> 生成移动端原型时**必须**逐条对照。这些是"真实 App 的基本常识"，不是可选优化。
> 违反任何一条 = 低级错误，交付前必须自查。

## 方法论：固化为主，调研为辅（避免低级问题的根本策略）

**原则：不靠"每次联网调研"（慢、费 token、结果不稳定），也不靠"拍脑袋"（会犯低级错误）。而是「调研一次 → 固化 → 永久复用」。**

| 场景 | 做法 |
|:--|:--|
| 通用设计常识（金刚区满格/箭头右对齐/详情图文/个人中心五层…） | **已固化成本文铁律**，直接遵守，不用调研 |
| 行业组件零件（电商金刚区/本地生活店铺卡/医疗问诊卡…） | **已固化进行业组件库**（`移动端组件-{行业}.md`），作为「零件清单」按需取用拼装，**非固定首页模板** |
| **项目级信息架构（这个项目首页该有哪些模块、怎么排序）** | **必须调研**该项目业务特性（场景/功能/竞品）→ 规划信息架构 → 去组件库挑零件拼装 → 缺失零件按「组件绘制规范」自绘 |
| 遇到「没有对应行业组件库的新行业/新玩法」 | **此时才联网调研**该行业真实 App 设计 → 调研完**立即固化**成新的行业组件库/铁律 → 下次直接复用 |

**核心认知**：真实设计师团队靠"设计规范库"复用，不会每次从头调研。本铁律就是这套规范库。每次暴露新问题 → 调研 + 固化一条 → 错误种类越来越少，形成「越用越聪明」的循环。禁止"每次做都联网调研"（低效）和"完全不调研就拍脑袋"（会犯低级错误）两个极端。

## 一、布局对称

1. **金刚区对称满格**：5 列宫格入口数必须是 5 或 10（整倍数），禁止 5+3 之类空位。
   - 8 个入口 → 要么改成 10 个，要么改 4 列宫格 4×2。
   - 4 列宫格入口数必须是 4 或 8。

## 二、营销区形态

2. **营销区横滑，不竖排**：秒杀/拼团/团购/优惠券商品用**横向滑动卡片**（一屏露出 3~4 个，可左右滑），禁止竖排列表。
3. **店铺推荐横滑**：首页"附近好店"用横向滑动的小卡片，禁止竖排一行行列表插在电商区块之间。

## 三、首页信息架构（项目级调研，禁止固化）

4. **首页信息架构按项目调研**：首页模块与顺序**禁止固化**为固定模板。必须先调研项目特性（业务场景/核心功能/竞品），规划该项目特有的信息架构，再从行业组件库挑零件拼装。电商聚合平台的「搜索→金刚区→banner→秒杀→瀑布流」只是**一种可能**，不是标准答案；宠物预约平台、内容社区等不同项目的信息架构完全不同，禁止照搬。
   - 若有本地生活店铺，单独成区块（横滑）或独立频道，禁止竖排插在电商营销区与商品流之间。

## 四、细节规范

5. **列表右箭头右对齐**：所有"列表项 + 右箭头"结构，箭头必须 `margin-left:auto` 贴最右（距右 padding），禁止跟在文字后面。
6. **角标与文字同行**：消息/标签的数字角标、红点用 `display:inline-flex`/`inline-block`，禁止块级导致换行。
7. **顶栏固定**：顶部标题栏不随内容滚动（绝对定位固定），禁止用 translateY 做"沉浸式隐藏"导致与状态栏重叠。
8. **二级页导航组件一致**：所有二级页面的返回按钮必须是「白底卡片 + 阴影 + 圆角」的 `.sub-page-back` 样式（禁止透明无底），标题必须水平居中（绝对定位居中，禁止靠左）。用 page 结构做二级跳转时，返回按钮用 `.back-btn`（已对齐该样式）并给顶栏加 `.has-back` 类触发标题居中。

## 五、内容完整性

9. **商品详情完整**：商品详情页必须含：主图 + 价格（含划线原价）+ 名称 + 销量 + 服务保障 + **商品参数表** + **图文描述** + **用户评价（星级+昵称）**。
10. **购物闭环完整**：浏览 → 详情 → 加购 → 结算（地址 + 商品清单 + 支付方式）→ 提交订单 → 订单状态流转。禁止"结算只弹 toast"。
11. **底部操作按钮固定**：详情页/下单页的底部操作按钮（立即购买/加入购物车/立即申购/确认提交等）必须用 `.detail-bar` 固定在页面底部（`position:absolute;bottom:0`），禁止放进内容流里需要滚动才能看到。`.detail-bar` 放 `sub-page-body` 外面，body 加 `padding-bottom:96px` 让位；禁止用 `position:relative` 覆盖固定定位。

## 六、交互真实

12. **列表可筛选**：订单状态 tab、消息分类 tab 必须真实筛选（点击后列表变化），禁止静态不响应。

## 七、个人中心

13. **会员模块紧凑**：个人中心（"我的"页）顶部用紧凑的「头像 + 昵称 + 会员等级标签」个人信息区（约 90px 高），禁止用大金橙会员卡占满半屏。完整的会员卡（权益宫格 + 开通按钮）放在「会员中心」子页，点个人中心头部进入。

## 八、组件绘制规范（组件库没有时自绘）

14. **自绘组件守设计常识**：行业组件库没有的组件必须自己绘制，**禁止因组件库没有就不做**。自绘组件必须遵守本文档全部设计常识（圆角/阴影/间距/箭头右对齐/数字等宽等），禁止画出自创风格的低质量组件。
