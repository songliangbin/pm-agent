# 闭环检查清单 v2.0

> PM Agent 接到需求后，在出活前必须执行的系统推演检查

---

## 一、四维闭环检查法

每个功能点必须通过四个维度的检查：

`
┌─────────────────────────────────────┐
│           功能点（如 Banner）        │
├─────────────────────────────────────┤
│  ① 展示 → 用户能看到什么            │
│  ② 管理 → 谁在哪里管理它            │
│  ③ 数据 → 数据存在哪里、怎么流转    │
│  ④ 权限 → 谁有权操作                │
└─────────────────────────────────────┘
`

闭环 = ①②③④ 全部存在且打通

## 二、通用闭环检查表

### 2.1 展示类元素
| 检查项 | ①展示 | ②管理 | ③数据 | ④权限 |
|:--|:--|:--|:--|:--|
| Banner/头图 | 首页展示 | 配置后台 | 数据接口 | 运营权限 |
| 首页推荐 | 推荐列表 | 推荐配置 | 推荐逻辑 | 运营权限 |
| 分类/标签 | 分类列表 | 类目管理 | 类目数据 | 平台运营 |
| 通知/消息 | 用户收件箱 | 通知发布 | 通知数据 | 运营权限 |
| 搜索 | 搜索入口 | 热词配置 | 搜索引擎 | 无 |

### 2.2 操作类元素
| 检查项 | ①展示 | ②管理 | ③数据 | ④权限 |
|:--|:--|:--|:--|:--|
| 发帖/发布 | 用户端提交 | 审核后台 | 内容数据库 | 需登录 |
| 审核 | 状态展示 | 审核列表 | 审核记录 | 管理员 |
| 举报 | 用户举报 | 举报处理 | 举报记录 | 管理员 |
| 注册/登录 | 注册页 | 审核列表 | 用户库 | 平台运营 |

### 2.3 异常场景闭环
| 异常场景 | 用户侧兜底 | 管理侧兜底 |
|:--|:--|:--|
| 网络异常 | 离线提示+缓存 | 操作日志 |
| 内容不存在 | 404/空状态 | 内容回收站 |
| 超时未操作 | 自动取消/刷新 | 超时记录+通知 |
| 输入非法 | 前端校验+提示 | 敏感词库过滤 |

## 三、状态机检查

- 每个业务对象的状态机是否完整？
- 状态流转是否可逆？哪些是终态？
- 每个状态下的操作权限是否明确？
- 状态变更是否有通知触发？

## 四、多端协同检查矩阵

示例：
`
                用户端    管理端
  内容发布        ✅        ✅审核
  内容管理        ✅浏览    ✅管理
  用户管理        ✅个人    ✅管理
  通知消息        ✅接收    ✅发布
  
  ✅ = 有对应功能   — = 不涉及
`

## 五、检查结果输出

Agent 完成闭环检查后，必须输出检查报告：

`
=== 闭环检查报告 ===

✅ 已闭环（X项）
  • Banner → 配置后台 → 运营权限 → 通过
  • 发帖 → 审核 → 通知 → 通过

⚠️ 未闭环（X项）- 需 PM 确认
  • 首页推荐 → 推荐规则后台 → 不存在
    建议：新增推荐规则管理功能至管理后台
`

未闭环项必须列出来跟 PM 确认后才能进入出活阶段。

## 六、UI 质感闭环检查（第五维度）

每个原型交付前，必须跑完质感检查：

### 5.1 阴影检查
- [ ] 所有卡片使用复合阴影（双层 box-shadow）
- [ ] 主按钮悬浮态有品牌色阴影
- [ ] 底部导航阴影为 XL 层级
- [ ] 无单层阴影冒充立体感的情况

### 5.2 毛玻璃检查
- [ ] 底部导航 `backdrop-filter` 包含 `blur(20px) saturate(180%)`
- [ ] 毛玻璃层有半透明边框 `rgba(255,255,255,0.3)`

### 5.3 图标检查
- [ ] 全站零 Emoji
- [ ] 底部导航图标是 24x24 SVG，stroke 1.5
- [ ] 按钮、列表项、空状态均无 Emoji

### 5.4 排版检查
- [ ] 标题（>=16px）有 `letter-spacing: -0.02em`
- [ ] 标签文字有 `letter-spacing: 0.01em`
- [ ] 价格/统计数字有 `font-variant-numeric: tabular-nums`

### 5.5 装饰检查
- [ ] 沉浸式头部或有特殊质感的区块有径向光斑
- [ ] 深色背景卡片有噪点纹理
- [ ] 渐变背景有叠加混合模式增强层次

### 5.6 交互检查
- [ ] 所有按钮有 `:active` 状态（scale 或背景变化）
- [ ] 卡片点击有 `transform: scale(0.985)` 反馈

## 七、多端协同检查矩阵（工作流必跑项）

检查每个功能在用户端/商家端/管理端/收银系统等各端的覆盖情况：

```
                用户端    商家端    管理端    收银系统
功能A            ✅浏览   ✅管理    ✅审核     —
功能B            ✅使用   —         ✅配置     —
  ✅ = 有对应功能   — = 不涉及   ⚠️ = 缺失需确认
```

多端矩阵必须与四维闭环检查 + UI质感检查一同输出。

## 八、文件命名与版本约定

- 初版：`{项目名}-需求文档.html` / `{项目名}-{端名}-交互原型.html`
- 迭代版：`{项目名}-需求文档_v2.html`（追加 `_v{N}` 后缀）
- 备份：不允许手动备份，使用 git 或归档文件夹
- 避免文件名中混入日期、修改人等信息
