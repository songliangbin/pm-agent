# UI 走查清单（UI/UX 专家走查依据，v5.21 建立）

> **定位**：生成移动端原型并截图后，主 Agent 以「UI/UX 专家」身份，按本清单**逐屏走查截图**，发现视觉/排版问题 → 定位到源码容器 → 修复 → 重新 build。本清单是"专家看图"的执行标准，与 lint/pm-review（机械规则）互补——机械规则拦"能写成规则的"，本清单补"必须用眼睛看才发现的"。

> **触发时机**：步骤⑤++ 运行 `ui-snapshot.py` 生成图集后，**必须**按本清单逐条走查（每条 ≤10 秒），任何一条不满足 → 记录问题 → 走「修复闭环」。

---

## 使用流程（主 Agent 走查动作）

```
① 运行 ui-snapshot.py 生成图集（_snapshots/index.html）
② 打开图集，逐屏走查，按本清单检查
③ 发现问题 → 记录：页面/元素/问题类型/截图序号
④ 定位源码：截图页面 → 对应注入文件（main.html/subpages.html/biz.js）→ 找容器/元素
⑤ 修复 → 重新 build → 重新截图 → 复验该条
⑥ 全部通过 → 交付说明中声明「UI 走查：通过 N/M 项」
```

## 修复闭环规则

1. **定位到源码容器**再改：截图 → 页面 id → 注入文件 → 容器/元素，禁止凭猜测改
2. **机械优先**：若问题可由 lint/pm-review 规则拦截 → 同步补规则（防复犯），不只改当前文件
3. **模板优先**：若问题源于模板缺失组件/类 → 先补模板，再改项目文件（机制同步铁律）
4. **复验**：修复后必须重新 build + 重新截图，确认该条通过，不能只改不验
