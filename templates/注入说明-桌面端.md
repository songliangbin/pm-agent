## 页面结构规范（pages.html）

- 每个页面：`<div class="page" id="page-{name}">`，默认页加 `active` 类
- 页面内：`.page-header`（h2 标题 + page-desc）+ 内容区
- 表格：`<table class="data-table"><thead>...<tbody id="{name}TableBody">`（tbody 由 JS 渲染）
- dashboard 页必须含 `id="dashRecentTable"` 的 tbody（模板 renderAll 默认渲染它）
- 侧边栏 nav-item 的 `data-page` 值必须与页面 id 对应（`page-{name}`）
- 按钮必须有真实 onclick（禁止仅 showToast 的伪功能按钮；无法实现则用 disabled 样式）

## 列表页筛选区结构（M19 铁律：大厂专业标准，每个列表页必须标配）

```html
<div class="table-toolbar">
  <div class="filter-bar">
    <!-- 关键词搜索（带放大镜图标 + Enter 快捷键） -->
    <div class="filter-search">
      <i class="fa-solid fa-magnifying-glass"></i>
      <input type="text" id="{name}Search" placeholder="搜索XXX" onkeydown="if(event.key==='Enter')filterXxx()">
    </div>
    <!-- 每类字段一个下拉筛选（带下拉箭头图标） -->
    <div class="filter-field">
      <select id="{name}TypeFilter"><option value="">全部类型</option>...</select>
      <i class="fa-solid fa-chevron-down"></i>
    </div>
    <div class="filter-field">
      <select id="{name}StatusFilter"><option value="">全部状态</option>...</select>
      <i class="fa-solid fa-chevron-down"></i>
    </div>
    <!-- 搜索 + 重置按钮组 -->
    <div class="filter-btn-group">
      <button class="btn-search" onclick="filterXxx()"><i class="fa-solid fa-magnifying-glass"></i>搜索</button>
      <button class="btn-reset" onclick="resetXxx()"><i class="fa-solid fa-rotate-left"></i>重置</button>
    </div>
  </div>
  <!-- 右侧操作区：导出（模板提供 exportTableCSV 通用函数） -->
  <div class="filter-actions">
    <button class="btn-export" onclick="exportTableCSV('{pageName}','{文件名}')"><i class="fa-solid fa-download"></i>导出</button>
  </div>
</div>
```

**筛选字段适配规则**（按列表字段自动适配，不只搜索+状态）：
- 有类型字段 → 加类型下拉（如商家类型/服务类型/寄养类型/活动类型）
- 有状态字段 → 加状态下拉（枚举值对齐契约状态机）
- 搜索框 placeholder 覆盖 2-3 个可搜索字段（如"搜索店铺名称/联系人/电话"）
- 筛选函数必须真实过滤 demoData（filterXxx 内实现），reset 函数清空所有条件并刷新
- 每次筛选/重置后调用导出按钮基于当前筛选结果导出

**JS 配套**：每个列表页必须有 `filterXxx()`（真实过滤）+ `resetXxx()`（清空条件刷新）两个函数。

## 侧边栏树形架构（M22 铁律：平台管理端全部菜单统一为「一级菜单 + 二级菜单」树形）

**平台管理端整个侧边栏必须全部使用树形结构**（禁止 nav-group-title 平铺 + 个别树形的混合结构）。每个业务分组 = 一个一级菜单（`.nav-parent`），分组下所有页面 = 二级菜单（`.nav-children`）：

<div class="nav-group">

  </div>
  <div class="nav-children">
    <a class="nav-item active" data-page="dashboard"><i class="nav-icon fa-solid fa-gauge-high"></i>数据看板</a>
    <a class="nav-item" data-page="stats"><i class="nav-icon fa-solid fa-chart-column"></i>数据统计</a>
  </div>
</div>
<div class="nav-group">
  <div class="nav-item nav-parent" onclick="toggleNavGroup(this)">
    <i class="nav-icon fa-solid fa-gear"></i>系统管理
    <i class="nav-chevron fa-solid fa-chevron-down"></i>

  </div>

**树形铁律**：
1. **全树形**：所有一级分组都用 nav-parent + nav-children（系统管理、运营管理、财务结算、内容运营、概览等），禁止"分组标题 + 平铺菜单"混合
2. **系统管理二级固定顺序**：我的组织 / 角色权限 / 菜单配置 / 字典配置 / [扩展菜单] / 操作日志
3. **nav-children 内子项**：`<a class="nav-item" data-page="{name}">`，点击自动 switchPage（模板机制性绑定，无需写 onclick）
4. **导航展开策略（M26 铁律）**：一级菜单数量 **≤10 个 → 一级+二级全部直接展开，无展开/收起功能**。模板自动加 `tree-all-open` 类，样式规范：**一级菜单 = 无图标小号分组标签**（11px 粗体、灰色、左对齐、无箭头、pointer-events:none 不可点击），**二级菜单 = 图标+文字可点击项**（13.5px、hover 高亮、active 高亮竖条），两级视觉差异化；**>10 个 → 大厂标准树形**：一级菜单 = 图标+文字+箭头（可点击展开），二级菜单默认全部折叠（点击展开、有 hover/active 态）。此逻辑由模板 initSidebar 自动判断，无需注入内容处理

**二级页面规范**：
1. **我的组织（page-org）**：**企业微信式组织架构**（`.org-layout` 左右布局，M27 铁律）——左侧 `.org-tree` 部门树：顶层部门 = 项目名称（如「宠宠到家」），下属二级部门（研发部/运营部/客服部等），默认选中顶层；右侧 `.org-members` 成员列表：字段含 **姓名/手机号/部门/角色/状态（启用/禁用）/操作**，选中部门后显示"当前部门（含子部门）共 X 名成员"并联动过滤；**必须实现部门与成员的完整增删改查**：部门（新增/重命名/删除，删除时成员移至顶层）、成员（新增/编辑/禁用启用/删除，弹窗含姓名/手机号/部门/角色）
2. **角色权限（page-roles）**：角色表（名称/角色说明/权限范围/成员数/状态 + 操作列[编辑/删除]，**无角色编码字段**）；**创建与编辑必须为两步向导**（M31/M32 铁律）——第 1 步：角色名称+角色说明；第 2 步：一级/二级菜单权限勾选树（`.perm-group` 按一级分组（概览/运营管理/财务结算/内容运营/系统管理）分组，组头全选 + 组内二级菜单复选框联动）；步骤条 `.wizard-steps` 展示进度，支持上一步/下一步；**操作按钮统一放弹窗底部 modal-footer（仅一组按钮）**：第 1 步 `[取消][下一步]`、第 2 步 `[上一步][取消][确定]`，body 内不放按钮；**确定即保存**（无独立"保存权限"按钮），保存写入 role.name/desc/menuIds 并自动更新权限范围描述；超级管理员禁止编辑/删除
3. **菜单配置（page-menus）**：菜单表（名称/路由/类型[目录|菜单|按钮]/排序/状态）
4. **字典配置（page-dicts）**：字典表（名称/编码/键值项/状态 + 操作列[编辑/删除]）；**必须实现字典增删改查**（M33 铁律）——新增字典（弹窗：名称/编码/键值项/状态，footer [取消][确定]）、编辑字典（footer [取消][保存]）、删除字典（确认弹窗 footer [取消][删除]），按钮统一放 modal-footer 仅一组
5. **操作日志（page-logs）**：日志表（操作人/模块/内容/IP/时间）
6. **数据与分页**：与 M20 一致（每个列表 10 条、每页 5 条、筛选区+导出+分页器）
7. **按钮真实功能**：编辑/配置权限等按钮必须打开真实弹窗（openModal 表单 + 保存），禁止 showToast 占位（I5/D10 强制拦截）

## 内容区配色规范（M28 铁律：禁止引用深色侧边栏变量）

**主题体系**：侧边栏 = 深色主题（`--sidebar-bg:#090a0f` 深黑底、`--sidebar-text:#8b8fa7` 浅灰字、hover `--sidebar-hover:#1a1c26` 深色块、active `--sidebar-active`）；**内容区 = 浅色主题**（白卡片 `--card:#fff`、黑字 `--text:#111827`、hover `#f9fafb` 浅灰、active `--accent-bg` 主色浅底）。

**配色铁律**：
1. **内容区任何组件（卡片/树节点/表格行/标签等）禁止引用深色侧边栏变量**（`--sidebar-hover`/`--sidebar-active`/`--sidebar-text`/`--sidebar-bg`），否则白底黑字配深黑 hover 色块直接冲突
2. **hover 态**：内容区用 `#f9fafb`（浅灰）或 `var(--accent-bg)`（主色浅底）+ 文字变主色
3. **active/选中态**：`var(--accent-bg)` 浅色底 + `var(--accent)` 主色文字/图标
4. **Lint C1-10 强制拦截**：内容区 CSS 引用深色侧边栏变量即构建失败

## 导出按钮规范（M30 铁律：仅业务数据列表页可导出）

**导出按钮只用于业务数据列表页**（商家管理/商家审核/用户管理/订单管理/退款管理/抽佣账单/结算管理/轮播图/分类/活动等有业务数据价值的列表）。

## 数据量与分页规范（M20 铁律：每个列表 10 条数据，每页 5 条）

1. **数据量统一**：每个列表的 demoData 数组必须 10 条（不足 10 条时按 id 序号偏移克隆补齐，保持字段值合理变化）
2. **每页 5 条**：渲染函数用模板通用分页（renderPager/gotoPage），切片渲染每页 5 条
3. **分页容器**：每个表格底部加：
```html
<div class="table-footer">
  <div class="pages" id="{name}Pager"></div>
</div>
```
4. **渲染函数分页模式**（模板 renderPager 自动生成页码/总数/上下页）：
```js
function filterXxx() {
  var list = demoData.xxx.filter(...);
  var tbody = document.getElementById('xxxTableBody');
  var __pg = __pagerState['xxxPager'] || { page: 1 };
  var __ps = 5;
  var __tp = Math.max(1, Math.ceil(list.length / __ps));
  var __p = Math.min(__pg.page || 1, __tp);
  var __sl = list.slice((__p - 1) * __ps, __p * __ps);
  tbody.innerHTML = __sl.map(...).join('');
  renderPager('xxxPager', __p, list.length, __ps, filterXxx);
}
```
5. **筛选与分页联动**：筛选后总条数变化，分页器自动更新（renderPager 以过滤后 list.length 为准）
6. **分页器布局（大厂标准）**：左侧显示「共 X 条」，右侧显示「上一页 | 页码 | 下一页」（模板 renderPager 已按此布局渲染，无需额外处理）

## accent-rgb 一致性铁律（M42 防护：--accent-rgb 必须与 --accent 匹配）

`--accent-rgb` 变量**必须与 `--accent` 主色 HEX 值匹配**，用于 `rgba(var(--accent-rgb), 0.X)` 阴影/光效计算。

### 规则

1. **必须替换 --accent-rgb**：模板默认值 `92,108,240`（蓝紫色），必须替换为项目主色对应的 RGB 三元组
2. **从 --accent HEX 转换**：如 `--accent: #00B96B` → `--accent-rgb: 0,185,107`（HEX → R,G,B）
3. **配置文件必须包含**：config.json 的 colors 对象中必须包含 `--accent-rgb` 键
4. **构建脚本自动修复**：如果遗漏，build 脚本会从 --accent 自动计算并修正（但不应依赖此兜底）
5. **禁止硬编码蓝紫色**：品牌渐变用 `var(--accent-hover)`，active文字用 `var(--accent-light)`，禁止 `#8b5cf6`/`#c7d2fe`/`#a5b4fc`


## 图表渲染铁律（M43 防护：柱状图必须有背景色 + 类名不得复用）

1. **.bar 柱体必须定义 background**：`linear-gradient(180deg,var(--accent),var(--accent-hover))`，否则柱子透明不可见
2. **禁止复用 .rank-bar 作整行容器**：`.rank-bar` 是 90px 宽条，整行排行用 `.rank-row`（flex 布局），类名不得跨界复用
3. **渲染后自检**：数据看板图表注入后必须肉眼验证柱体可见、排行条整行铺满


## 图表高度与间距铁律（M44 防护：柱状图必须像素高度 + 排行行留白）

1. **柱状图 .bar 高度必须用像素**：`height:X%` 在 flex-auto 父容器（.bar-col）中无法解析，所有柱子会等高塌缩。正确写法：`var chartH = 140; var hpx = Math.round(d.value / maxV * chartH); style="height:' + hpx + 'px"`
2. **排行行必须留白**：类目排行（.rank-row）左右 padding 24px，与 card-header 对齐，禁止内容贴卡片边缘
3. **示例数据必须真实**：趋势图数据要有升有降的波动（工作日波动、周末峰值），并用具体日期（如 07/27）而非 周一/周二

## 弹窗 vs 二级页面决策铁律（M46 防护：字段多/查看型必须二级页面）

**任何操作入口生成前，必须走以下决策树自动判断，禁止凭感觉：**

```
操作入口（列表行/按钮）
    ├─ 确认类（删除/下架/驳回确认）──────────────→ 弹窗 ✅
    ├─ 轻量表单（≤6 字段：新增/编辑类目/字典/成员等）→ 弹窗 ✅
    ├─ 多步流程（如角色向导两步）───────────────→ 弹窗（步骤条）✅
    └─ 查看/详情类 → 判断字段量与结构：
          ├─ 字段 ≤8 且无图片/长描述/材料 → 弹窗 ✅
          └─ 字段 >8 或含图片/长描述/材料预览
               或详情内还要继续操作（审核/驳回/下架）
               → 二级页面 ✅（禁止弹窗）
```

### 量化阈值表

| 维度 | 弹窗 | 二级页面 |
|:---|:---|:---|
| 字段数量 | ≤6（表单）/ ≤8（查看） | >8 |
| 内容形态 | 纯文本短字段 | 含图片/长描述/材料/时间轴 |
| 操作类型 | 新增/编辑/确认/单步处理 | 查看为主或详情内嵌操作 |
| 信息层级 | 单层扁平 | 需分组排版（基本信息/交易/统计） |
| 使用频率 | 低频操作 | 高频反复查看 |

经验法则：**能 3 秒看完/填完 → 弹窗；需仔细阅读/反复对照/还要继续操作 → 二级页面。**

### 二级页面实现规范（模板已内置基础设施）

1. **容器**：`<div class="page" id="page-xxxDetail">` 放在 PAGE_START/END 内，用 `.detail-header` 结构：
   - 左侧 `.detail-back` 返回按钮（onclick="goBackFromDetail()"）
   - 中间 `.detail-title`（标题 + 状态 tag）+ `.detail-sub`（摘要信息）
   - 右侧 `.detail-actions` 操作区（审核/驳回/下架等按钮）
2. **内容分组**：`.detail-cards > .detail-card`（可 `.full` 通栏）> `.detail-card-title`（带图标）+ `.detail-grid > .detail-item(.dl/.dv)`；金额用 `.dv.amount` 高亮
3. **打开**：`openDetailPage('xxxDetail', {back:'来源页', path:'模块 / 列表页 / ', title:'标题'})`；返回自动回到来源页，面包屑显示层级（如 商品管理 / 商品列表 / 商品详情）
4. **详情内操作**：通过/驳回/下架等按钮放 `.detail-actions`，操作完成后 `goBackFromDetail()` 返回并刷新列表
5. **时间轴**：订单等状态流转用 `.detail-timeline > .tl-item(.done/.current/.cancel)`
6. **材料预览**：认证材料等用 `.material-preview > .material-card(.m-img/.m-name)`
7. **禁止**：详情字段 >8 仍用 openModal 塞进弹窗（M46 拦截强制失败）


## 列表→详情判定铁律（M47 防护：生成每个列表前先判定是否需要详情按钮）

**核心原则：列表是"索引"，详情是"全文"。列表无法完整呈现一条记录的全部信息时，就需要详情入口。**

生成任何列表前，按以下 5 维依次判定（任一命中"需详情"即需要详情按钮）：

| 维度 | 需要详情 ✅ | 无需详情 ❌ |
|:---|:---|:---|
| ① 信息完整性 | 记录有列表未展示的关键字段（长描述/地址/材料/明细） | 列表列已覆盖全部字段 |
| ② 操作承载 | 处置需看全貌再决定（审核类）或操作复杂（多状态流转） | 单按钮操作（封禁/下架）行内即可 |
| ③ 关联跳转 | 记录关联其他实体（订单/商品/用户），详情可提供跳转 | 无关联对象 |
| ④ 字段数量 | 总字段 >8 需分组排版 | 字段 ≤8 平铺即可 |
| ⑤ 可编辑性 | 查看型为主 | 基础配置类，字段少直接弹窗编辑 |

记忆口诀：**有隐藏字段要详情、有审核要详情、有关联要详情、字段多要详情；纯流水、纯配置、单操作不要详情。**

### 详情页操作承载规范

1. **操作双入口**：详情页 `.detail-actions` 承载主要操作（封禁/通过/驳回/打款），**列表行保留快捷操作按钮**，两者不冲突
2. **操作后返回**：详情页内操作完成后调用 `goBackFromDetail()` 自动返回来源列表
3. **关联跳转**：详情内订单号/商品号/用户等关联对象用可点击链接（`<a href="javascript:void(0)" onclick="goToOrderDetail('xxx')">`），跳转目标详情后返回时回到跳转来源
4. **典型判定示例**：
   - 用户列表 → 有隐藏字段（真实姓名/学号/认证）+ 关联商品 → 需详情 ✅
   - 交易流水/分账 → 关联订单可跳转 → 需详情 ✅
   - 提现审核 → 审核类多状态 → 需详情 ✅
   - 举报 → 长文本描述 + 需处理 → 需详情 ✅
   - 操作日志 → 纯审计流水无隐藏字段 → 无需详情 ✅
   - 分类/学校/Banner/菜单/字典 → 字段全暴露 + 弹窗编辑 → 无需详情 ✅


## 弹窗双模式铁律（M48 防护：单参 openModal 必须对应静态弹窗）

模板 openModal 支持**双模式**，生成表单弹窗时必须选对模式，禁止混用：

1. **静态模式（表单弹窗）**：`openModal('categoryEdit')` 单参调用 —— 表单 HTML 直接写在 `<div class="modal-overlay" id="categoryEdit-overlay">` 中（modal-header/modal-body/modal-footer 完整），openModal 按 id 打开对应静态弹窗。**适用于：新增/编辑类目、Banner、部门、成员、学校、菜单、字典、删除确认、两步向导（roleWizard）等**
2. **动态模式（内容弹窗）**：`openModal(title, htmlContent, footerHtml)` 三参调用 —— 内容由 JS 拼 HTML 填充到通用 modalOverlay。**适用于：驳回理由、动态详情等少量字段弹窗**
3. **调用前必须确认**：单参 openModal('xxx') 必须在 HTML 中存在 `<div id="xxx-overlay">` 静态弹窗且 modal-body 内**必须有表单字段**（禁止空 body 弹窗）
4. **关闭兼容**：静态弹窗关闭按钮用 `closeModal('xxx')`，背景点击由 openModal 自动绑定 `closeModal(event)`；动态弹窗用 `closeModal()`

## 列表响应式设计铁律（D29 防护：禁横向滚动 + 字段进详情 + 按钮折叠）

**背景**：用户反馈 V1/V2/V3 模板的列表页在 7+ 字段 + 多按钮操作时，会出现「操作列按钮被截断、表头背景断裂、横向滚动条遮挡内容」等致命问题。

**铁律**：

1. **禁止 `.table-wrap` 使用 `overflow-x:auto`**（禁横向滚动条）。V1/V2/V3 模板已统一 `.table-wrap{overflow:visible}`，生成 HTML 禁止覆盖
2. **列表字段 ≤ 7 列**（含操作列）：超过 7 列必须把次要字段移入详情页。例如：
   - 退款管理 8 字段 → 减到 7，把「关联订单」移入详情（用户点详情本来就跳转）
   - 订单管理 8 字段 → 减到 7，把「卖家」/「长描述」移入详情
   - 用户列表 8 字段 → 减到 7，把「学校」/「注册时间」移入详情
   - 举报处理 8 字段 → 减到 7，把「举报原因」长字段移入详情
3. **操作列按钮 ≤ 3 个**：超过 3 个的折叠成「更多」下拉（V2/V3 模板已提供 `.dropdown` + `.dropdown-menu` 组件 + `toggleDropdown()` 函数）
   - 使用示例：
   ```html
   <td class="action-col">
     <button class="btn btn-sm btn-primary">同意退款</button>
     <button class="btn btn-sm btn-danger">拒绝</button>
     <div class="dropdown">
       <button class="btn btn-sm btn-default" onclick="toggleDropdown(this)">更多 ▾</button>
       <div class="dropdown-menu">
         <button onclick="openOrderDetail('xxx')"><i class="fa-solid fa-eye"></i>订单详情</button>
         <button class="btn-danger" onclick="refundBlock('xxx')"><i class="fa-solid fa-ban"></i>永久封禁</button>
       </div>
     </div>
   </td>
   ```
4. **字段超长自动 ellipsis 截断**：模板已统一 `td{overflow:hidden;text-overflow:ellipsis;white-space:nowrap}` + `table-layout:fixed` + `max-width:0` 触发 ellipsis
5. **操作列不截断**：`.action-col{overflow:visible;flex-wrap:wrap;max-width:none}` + `min-width:180px`，按钮可换行但不许消失
6. **校验**：agent-lint **C1-21** 静态扫描 `.table-wrap` 不得含 `overflow-x:auto`；**C1-22** 列表 thead 列数 ≤ 7；**C1-23** `td.action-col` 按钮 ≤ 3 个（折叠下拉内不计）

## 下拉菜单位置铁律（D29-2 防护：dropdown 必须 fixed 定位）

**背景**：用户实测「校园集市管理端」用户列表点「更多」后，下拉菜单里「封禁账号」「查看学校」两个按钮挤在同一行无法点击。原因不是 CSS 没写，而是 `td{overflow:hidden}` 把 absolute 定位的子元素裁剪成 0 宽窄条。

**铁律**：

1. **`.dropdown-menu` 必须用 `position:fixed`**——不能 `position:absolute`。原因：`td` 为 ellipsis 设置了 `overflow:hidden`，absolute 定位的子元素无论声明多少 width 都会被裁剪成父容器宽度（在这里≈0px），导致 `display:flex` 的按钮水平堆叠重叠
2. **JS 必须强制 layout 后再算 left/top**：`getComputedStyle(menu).width` 触发浏览器计算（否则 `display:none → block` 切换瞬间 `offsetWidth=0`，菜单飞到坐标 0,0），再用 `getBoundingClientRect()` 取 trigger 位置
3. **视口外 fallback**：`rect.right ≤ 0` 时 `left=100, top=100`（避免菜单飞到视口外不可见）
4. **校验**：
   - agent-lint **C1-24** 静态扫描 `.dropdown-menu` 直接定义必须含 `position:fixed`（**fail 级**，模拟旧版 absolute 已验证可拦截）
   - browser-check **B7** 实际触发 dropdown，断言菜单 `display:block` + `width≥100px` + `x` 在视口内（不是静态检查，是真实点击验证）
5. **示例（toggleDropdown 必须含 layout 强制与视口判断）**：
   ```javascript
   function toggleDropdown(el){
     var w=el.closest('.dropdown');
     if(!w) return;
     var wasOpen=w.classList.contains('open');
     document.querySelectorAll('.dropdown.open').forEach(function(d){d.classList.remove('open')});
     if(!wasOpen){
       w.classList.add('open');
       var menu=w.querySelector('.dropdown-menu');
       if(menu){
         getComputedStyle(menu).width;  // 强制 layout
         var rect=w.getBoundingClientRect();
         var mw=menu.offsetWidth || 140;
         var left=rect.right>0 ? (rect.right - mw) : 100;
         var top=rect.bottom>0 ? (rect.bottom + 4) : 100;
         menu.style.left=left + 'px';
         menu.style.top=top + 'px';
       }
     }
   }
   ```

## Build 产物校验铁律（D30 防护：禁止手工 patch build 产物 CSS）

**背景**：用户上一轮我只改了模板 CSS，但「校园集市」原型（build 产物）内联的 CSS 还是旧的，导致 D29 修复无效、用户实测仍出问题。**根因**：手工改 HTML 而不是重新 build，会让模板与产物永远漂移。

**铁律**：

1. **build 产物禁止手工 patch CSS/JS**：任何对模板样式的改动必须改 `templates/prototype-desktop*.html` 模板本身，然后**重跑 build-prototype.py** 重新生成原型
2. **build 后必须 verify-all 全绿**：lint + browser-check + 副本同步 全部通过才能交付
3. **用户看到问题的处理流程**：
   - 第一步：用 `lint` 看是否有 fail 项（C1-21/22/23/24/25 是 D29/D29-2/D31 防护）
   - 第二步：用 `browser-check` 看是否有 fail（B7 是 dropdown 实际渲染验证，B8 是重复按钮验证）
   - 第三步：定位根因 → 改**模板** → 重 build → 再 verify-all
4. **不要相信「原型已经生成就 OK」**：build 产物可能因历史 patch 漂移，必须每次都跑 verify-all

## 操作按钮唯一位置铁律（D31 防护：新增/导出按钮只能放一处）

**背景**：用户实测「系统管理/角色权限」出现两个「新增角色」按钮。根因是 V2 模板的 M51 系统管理标准模块把「新增」按钮同时写在 ① 静态 HTML `.filter-actions` 和 ② `PAGE_META.xxx.actions`（页头右侧）两处。

**铁律**：

1. **「新增」「导出」等页头操作按钮统一放 `PAGE_META.actions`**（页头右侧，switchPage 自动渲染），**`.filter-actions` 保持空**（或只放批量操作如「批量删除」，但当前模板无此场景）
2. **同一个操作按钮只能出现一次**：禁止在 `.filter-actions` 静态 HTML 和 `PAGE_META.actions` 两处同时定义同一个按钮（相同 onclick 函数）
3. **系统管理标准模块（M51）的 roles/menus/dicts 页面**：「新增角色/新增菜单/新增字典」已在 `PAGE_META.actions` 定义，`.filter-actions` 必须为空
4. **校验**：
   - agent-lint **C1-25** 提取 `PAGE_META.actions` 的 onclick 函数名集合 A 与 `.filter-actions` 按钮 onclick 集合 B，A∩B 非空即 fail（**模板也检查**，模板自带重复必须拦截）
   - browser-check **B8** 实际渲染后检查 `#pageActions` 与 `.filter-actions` 按钮文字交集
