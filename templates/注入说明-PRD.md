# PRD 注入说明（子 Agent 读取，替代完整模板）

> 你**不需要**读取 `templates/prd-template.html`（107KB）。只需按本文档产出 4 个注入文件，主 Agent 用 `scripts/build-prototype.py` 确定性拼装。
> **一个项目只产出一份 PRD**（由主 Agent 汇合生成），不产出分端 PRD 章节。

## 你的产出（4 个文件）

| 文件 | 内容 | 大小上限 |
|:--|:--|:--|
| `nav.html` | 侧边栏导航（含三层结构分组标题） | ≤ 4KB |
| `sections.html` | 全部章节 HTML（tab-content 结构） | ≤ 70KB |
| `section-index.js` | 搜索索引（const sectionIndex = [...]） | ≤ 3KB |
| `knowledge-base.js` | 知识库 + 同义词（const knowledgeBase/synonymMap） | ≤ 6KB |

## 模板已提供的设施（禁止重复定义）

`showSection`、`doSearch`、`findAnswer`、`toggleChat`、`sendMessage`、`jumpToSection`、`askBot`、`sendQuick` 均由模板提供，**禁止重新定义**。注入数据只替换 sectionIndex/knowledgeBase/synonymMap 数组内容。

## 三层结构（铁律，违反即不合格）

侧边栏必须含 4 个分组标题，章节归属如下：

| 分组 | 必含章节 |
|:--|:--|
| 决策层 | 系统首页(#home) / 项目概述(#overview) / 用户研究(#user-research) / 业务目标(#business-goals) / 功能规划(#feature-plan) |
| 方案层 | 系统架构(#architecture) / 功能入口方案对比(#entry-comparison) / 解决方案对比(#solution-comparison) / 成本与ROI(#cost-roi) / 项目排期(#schedule) / 风险管理(#risk-management) |
| 实现层 | 角色权限(#roles) / 核心业务模块（按实体，含状态机+流程图+规则表）/ 功能详细设计 / 数据结构(#data-structure) / 接口设计(#api-design) / 测试验收(#testing) |
| 附录 | 变更记录(#changelog) / 待确认问题(#pending-questions) / 评审意见(#review-records) / 参考资料(#references) |

## 章节 HTML 规范（sections.html）

- 每个章节：`<section id="{name}" class="tab-content">`，首页 section 加 `active`
- 章节标题：`<h2 class="section-title">` + `<p class="section-subtitle">`
- 表格：`<table class="prd-table">`（表头 thead + tbody），数据表 ≥ 3 行
- **卡片类名铁律（D37）**：卡片容器统一写 `<div class="card">`（模板已内置 .card 兜底样式：白底/边框/圆角/内边距/阴影）。**禁止**只写 `class="card"` 以外的变体（如 `class="card-hover"`、`class="bg-white rounded-2xl"` 混用）——Tailwind 原子类仅在 CDN 加载时生效，模板 .card 兜底保证离线也正常。需要 hover 效果时追加 `card-hover` 类：`class="card card-hover"`。
- 业务模块必须含：状态机（mermaid stateDiagram-v2）+ 流程图（mermaid flowchart）+ 规则表（prd-table）
- 用户可见提示文案必须写清楚（禁止"开发中"占位）

## 数据规范

- sectionIndex：每个章节一条 `{ id, title, keywords }`，keywords 覆盖搜索意图（≥4 个/条）
- knowledgeBase：**≥ 10 条**，每条 `{ keywords[], answer, goto }`，answer 用 HTML 加粗强调，goto 指向对应章节 id
- synonymMap：≥ 10 组同义词映射（关键业务术语）

## nav.html 结构铁律（P13 防护：CSS/JS 类名必须与模板一致）

模板 CSS/JS 使用 `.nav-item` 类和 `onclick="showSection('id')"` 属性管理导航高亮。
注入的 nav.html **必须遵守以下结构**，否则高亮失效：

1. **类名必须用 `nav-item`**（禁止用 `sidebar-item`、`menu-item` 等其他类名）
2. **必须保留 `href="#{章节id}"` 属性**（用于无障碍和备用定位）
3. **必须保留 `onclick="showSection('{章节id}')"` 属性**（用于切换章节）
4. **分组标题用 `nav-group` + `nav-group-title`**（禁止内联 style 做分组标题）
5. **图标用内联 SVG 加 `nav-icon` 类** 或 Font Awesome `<i>` 标签（二选一，全文档统一）
6. **默认选中项加 `active` 类**（首页 `nav-item active`）

### 标准结构示例

```html
<div class="nav-group">
  <div class="nav-group-title">决策层</div>
  <a href="#home" class="nav-item active" onclick="showSection('home')">
    <svg class="nav-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2">
      <path d="M3 12l9-9 9 9M5 10v10h14V10"/>
    </svg>
    <span>系统首页</span>
  </a>
  <a href="#overview" class="nav-item" onclick="showSection('overview')">
    <svg class="nav-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2">
      <path d="M9 11H5a2 2 0 00-2 2v7h6M9 3h6v6H9zM15 11h6v10h-6"/>
    </svg>
    <span>项目概述</span>
  </a>
</div>
```

> **禁止**：自创类名、省略 href、用内联 style 替代 nav-group-title、混用 Font Awesome 和 SVG 图标。

## 货币符号铁律（P14 防护：禁止美元符号 $）

文档中所有涉及金额的地方**必须使用人民币符号 ¥**，**禁止使用美元符号 $**。

- 正确：`¥100`、`¥ 99.50`、`佣金比例 3%（¥3）`
- 错误：`$100`、`$ 99.50`、`$3`
- 注意：JavaScript 模板字符串中的 `${variable}` 不是货币符号，不在此规则范围内
- 适用范围：章节正文、表格数据、知识库答案、成本 ROI 表格、价格字段等所有用户可见文本
- **图标也禁止美元符号**：导航项/按钮的 SVG 图标 path 不得使用美元符号 $ 形状（特征：中间竖线 `M x y v z` + 两侧 S 形弯曲），成本/ROI 用计算器图标，提现/钱包用钱包图标

## 原型链接铁律（P15 防护：原型入口必须可跳转）

"原型与UI"章节中的"打开原型"按钮**必须使用相对路径指向实际原型文件**，禁止 `javascript:void(0)` 空链接。

### 规则

1. **href 必须是相对路径**：如 `href="用户端原型.html"`、`href="平台管理端原型.html"`
2. **必须加 `target="_blank"`**：在新标签页打开原型，不离开需求文档
3. **文件名必须与实际输出文件名一致**：主 Agent 生成原型时 `--out` 参数的文件名即链接目标
4. **禁止** `javascript:void(0)`、`#`、`onclick="alert('开发中')"` 等无效链接
5. **如果原型文件尚未生成**：链接仍指向预期文件名（用户后续放置同名文件即可跳转）

### 标准结构示例

```html
<!-- 用户端原型 -->
<a href="用户端原型.html" target="_blank" class="...">
  <i class="fas fa-external-link-alt"></i> 打开原型
</a>

<!-- 管理端原型 -->
<a href="平台管理端原型.html" target="_blank" class="...">
  <i class="fas fa-external-link-alt"></i> 打开原型
</a>
```

> **文件名来源**：契约端矩阵的"输出文件名"列。主 Agent 生成原型时 `--out` 参数必须使用该文件名，需求文档中的 href 也必须使用该文件名。
> 所有交付物（需求文档 + 各端原型）放在同一目录下，使用相对路径即可互相跳转。
> **生成顺序不影响**：无论需求文档先生成还是原型先生成，只要最终文件名一致、在同一目录下，链接即可正常跳转。


## API 设计参数一致性铁律（P16 防护：禁止接口参数复制粘贴残留）

每个接口的请求参数**必须与该接口的功能直接相关**，禁止从其他接口复制参数后未清理无关字段。

### 规则

1. **参数必须匹配接口功能**：如"获取商品详情"接口不应包含 `keyword`（搜索关键词）、`categoryId`（分类ID）等搜索类参数
2. **禁止跨接口复制不清除**：分页参数（page/pageSize）可通用，但业务参数必须逐一核对
3. **公共参数例外**：`page`、`pageSize`、`token`、`timestamp` 等通用参数可跨接口使用
4. **每个接口必须独立设计参数**：即使接口间有相似性，也必须根据接口实际功能定制参数列表

## 功能设计参数表铁律（P17 防护：参数表字段必须与功能相关）

功能设计中的参数表**每个字段必须与该功能直接相关**，禁止混入其他功能的字段。

### 规则

1. **字段必须匹配功能**：如"发布商品"功能的参数表不应包含 `审核状态`、`拒绝原因` 等审核流程字段
2. **禁止跨功能复制不清除**：复制参数表模板后必须删除不相关字段
3. **每个功能独立设计参数**：根据功能实际输入输出定制字段

## 评审意见一致性铁律（P18 防护：评审意见与实际内容必须一致）

评审意见栏标注的修改建议**必须与文档实际内容一致**，关键数值（时间、阈值、比例等）在文档各处保持统一。

### 规则

1. **关键数值全文档统一**：如"自动完成时间"在状态机、时序图、规则表、评审意见中必须一致
2. **评审意见反映最终内容**：评审意见中标注"改为X"的，实际内容必须已经是X
3. **修改内容时同步评审意见**：调整任何关键数值时，必须检查并更新所有引用该数值的位置

## 配色方案一致性铁律（P19 防护：PRD 主色必须与项目契约一致）

PRD 文档的 CSS 主色变量**必须与项目契约中约定的配色方案一致**，禁止使用模板默认色。

### 规则

1. **从契约读取主色**：`--prd-primary` 等 CSS 变量必须使用契约中约定的主色值
2. **禁止使用模板默认色**：模板默认色 `#2563eb`（蓝色）仅在未指定时使用，有契约主色必须替换
3. **全文档配色统一**：所有引用主色的位置（按钮、高亮、标签等）必须使用同一主色值
4. **替换时机**：主 Agent 生成 PRD 时第一步即从契约读取主色并替换模板默认值

## 页面数量一致性铁律（P20 防护：页面统计全文档统一）

PRD 文档中所有提及页面数量的位置**必须数值一致**，包括工作量统计、原型页面清单、功能模块清单等。

### 规则

1. **页面数量单一来源**：以功能模块清单为基准，其他位置引用同一数值
2. **分端统计清晰**：用户端页面数、管理端页面数分别统计，不混用
3. **修改时全局同步**：增减页面时必须更新所有引用页面数量的位置

## 工作量统计铁律（P21 防护：工作量必须可理解）

工作量统计表**必须包含计算说明**，让读者能理解人天估算的依据。

### 规则

1. **必须有说明列**：工作量表包含"计算说明"或"备注"列，说明人天估算依据
2. **分角色估算**：前端/后端/设计/测试分别估算，不混为一行
3. **总计行清晰**：总人天 = 各角色人天之和，明确标注
4. **与功能模块对应**：工作量按功能模块拆分，不笼统给一个总数

## 数据结构完整性铁律（P22 防护：数据结构必须覆盖所有功能模块）

数据结构设计**必须覆盖所有功能模块涉及的数据表**，接口设计必须与数据结构配套。

### 规则

1. **表覆盖完整**：功能模块清单中每个模块涉及的实体都必须有对应数据表
2. **禁止遗漏辅助表**：支付记录、地址、聊天消息、举报、评价等辅助表必须包含
3. **接口与表配套**：每个数据表至少有对应的 CRUD 接口（或子集）
4. **字段设计规范**：每张表必须有主键、创建时间、更新时间等基础字段

## 文档信息表铁律（P23 防护：PRD 必须包含标准文档信息表）

PRD 文档**必须在开头（首页或项目概述后）包含标准文档信息表**。

### 规则

1. **必须包含字段**：文档名称、文档版本、文档状态、编写人、创建日期、最后更新、评审状态、密级、适用范围
2. **位置**：放在首页之后、项目概述之前或之中
3. **格式**：使用标准表格，与文档整体风格一致
4. **状态标签**：草稿/评审中/已发布 等状态用颜色标签区分

## 页面交互设计完整性铁律（P24 防护：交互设计必须覆盖所有端）

页面交互设计章节**必须覆盖所有端（用户端+管理端）**，包含关键页面流程说明。

### 规则

1. **分端描述**：用户端交互和管理端交互分别描述
2. **关键流程**：至少包含 3 个关键业务流程的交互说明（如注册登录、核心交易、订单管理）
3. **异常交互**：包含网络异常、数据为空等异常场景的交互说明
4. **与功能设计呼应**：交互设计中的页面/功能与功能模块清单一致

## 功能模块清单铁律（P25 防护：PRD 必须包含功能模块清单）

PRD 文档**必须包含"功能模块清单"章节**，以列表形式列出所有功能模块。

### 规则

1. **必须存在**：在决策层或方案层中包含"功能模块清单"章节
2. **列表格式**：每个模块一行，包含模块名称和功能简述（不使用表格，使用列表）
3. **覆盖完整**：清单中的模块必须覆盖所有功能（与功能设计章节一致）
4. **分端标注**：每个模块标注所属端（用户端/管理端/通用）

## 原型页面清单铁律（P26 防护：原型与UI章节必须包含页面清单）

"原型与UI"章节**必须包含原型页面清单**，分端列出原型包含的所有页面。

### 规则

1. **分端列出**：用户端页面清单和管理端页面清单分别列出
2. **页面名称**：每个页面有清晰的名称（如"首页"、"商品详情"、"订单管理"）
3. **页面数量**：清单中的页面数量必须与工作量统计中的页面数量一致（P20）
4. **与原型入口配套**：页面清单放在原型入口按钮附近，方便对照


## 架构图布局铁律（P27 防护：禁止 biz-panorama 与内部 grid 混用）

`.biz-panorama` 类**仅用于平台全景图（4列等宽卡片）**，不适用于其他场景。架构图等2列布局使用 Tailwind `grid grid-cols-2`，**不要叠加 `biz-panorama`**。

### 规则

1. **biz-panorama 仅限4列全景图**：`.biz-panorama` 设置了 `display:grid; grid-template-columns:repeat(4,1fr)`，会将所有子元素放入4列网格
2. **架构图用 biz-flow + Tailwind grid**：架构图容器使用 `class="biz-flow"`（仅背景/边框/内边距），内部用 `class="grid grid-cols-2 gap-4"` 控制布局
3. **禁止混用**：`biz-panorama` 与内部 `grid grid-cols-N` 同时使用会导致内部内容被压缩到1列宽度
4. **biz-flow 可单独使用**：`biz-flow` 只提供容器样式（渐变背景、圆角、边框、内边距），不影响内部布局



## CSS 硬编码颜色一致性铁律（P28 防护：交互元素颜色必须使用 CSS 变量）

模板 CSS 中所有引用主色的交互元素**必须使用 `var(--prd-primary)` 等 CSS 变量**，禁止硬编码 `#2563eb` 或 `rgba(37,99,235,...)`。

### 规则

1. **导航栏 hover/active**：必须用 `var(--prd-primary)` 和 `var(--prd-primary-bg)`，禁止硬编码颜色值
2. **提示框 prd-tip**：必须用 `var(--prd-info)` 和 `var(--prd-info-bg)`，禁止硬编码
3. **阴影颜色**：需使用主色的阴影用 `rgba(var(--prd-primary-rgb), 0.X)`，`--prd-primary-rgb` 是主色的 RGB 三元组（如 `0, 185, 107`）
4. **Agent 必须替换 --prd-primary-rgb**：替换主色时同步替换 `--prd-primary-rgb` 变量值（从主色 HEX 转换为 RGB 三元组）
5. **豁免项**：`.biz-node.blue`、`.sw-node.blue`、`.biz-ladder-card.blue` 等多色变体类中的蓝色是设计变体，不需要修改

## 导航图标规范（P29/P30 铁律：Lucide 顶级线性图标 + 描边样式）

**背景**：历史教训——①左侧导航 SVG 图标若只设尺寸不设 `fill/stroke`，path 默认 `fill:black`，线条型图标渲染为 0 宽度不可见、闭合型图标变黑色实心块；②手绘简单 path（如 `M12 3v18M3 12h18`）图标质量差，用户明确要求"顶级 UI 设计的高标准图标"。

**铁律**：
