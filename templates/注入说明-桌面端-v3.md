# 注入说明 — 桌面端 V3「现代侧栏仪表盘 (Modern Sidebar Dashboard)」

> 配套模板：`templates/prototype-desktop-v3.html`（约 98KB，电池内置设计系统 + JS 组件助手）
> 适用：现代 SaaS / 研发协作平台 / 工具型中台 / 想要「GitLab / Coding / Gitea 式左侧栏 + 顶部轻栏 + 卡片网格工作台」观感的项目
> 不适用：① 极重后台（超复杂左树右表、深度权限树编辑）→ 选 V1（`prototype-desktop.html`）；② 想要「顶部横向唯一主导航（无左栏）+ 内容全宽 + 右栏系统通知」的驾驶舱观感 → 选 V2（`prototype-desktop-v2.html`，`注入说明-桌面端-v2.md`）
>
> ⚠️ **V3 已标配「系统管理」**：模板永久区内置「系统设置」分组（侧栏一级分组，含 5 个二级：我的组织 / 角色权限 / 菜单配置 / 字典配置 / 操作日志），含 5 页 + 6 弹窗 + 全套 JS 函数，**与 V1/V2 功能对齐**。需要系统管理的项目也能直接用 V3，无需退回 V1/V2。详见 §8。

## 1. 与 V1 / V2 的核心差异（务必先读）

| 维度 | V1 经典管理后台 | V2 企业驾驶舱 | **V3 现代侧栏仪表盘** |
|:--|:--|:--|:--|
| 导航形态 | 左侧 240px 固定侧栏（多级树） | 顶部横向导航栏（可折叠） | **左侧 ~212px 窄侧栏（可折叠至 56px）+ 分组折叠** |
| 顶栏 | 无（侧栏承担导航） | 顶栏含导航+面包屑+操作 | **轻顶栏（~48px）：面包屑 + 搜索 + 通知 + 用户（V3 无项目切换器，见 §2.5）** |
| 首页 | 单页 dashboard | 工作台网格（KPI+应用宫格+待办） | **卡片网格工作台（KPI 4 列 + 仓库/文件 2 列 + 折线/环图 2 列 + 待办）** |
| 内容布局 | 侧栏 + 主内容独立滚动 | 顶栏 + `.workbench`（左滚动/右 `#rightRail`） | `.app`（横向 flex）→ `.sidebar` + `.app-main`（顶栏 + `.content-scroll` + `#rightRail`） |
| 视觉基调 | 白底 + 主色强调 | 浅蓝灰底 + 白卡 + 极淡阴影 | **靛蓝主色 `#6366F1` + 页面底 `#f5f7fa` + 白卡 + 圆角 6/8/12/16 + 极淡阴影 + 比 V2 更紧凑** |
| 系统管理入口 | 侧栏树形一级 | 顶栏「一级+下拉二级」 | **侧栏「系统设置」分组（与业务工作台分组并列）** |
| 图表 | 依赖外部库风险 | 零依赖内联 SVG 助手 | **零依赖内联 SVG 助手（同 V2）** |

> 三者共享同一套「注入式生成范式」：`nav / pages / data / biz` 注入文件 + `build-prototype.py` 确定性拼装 + lint + browser-check。
> V3 复用 V2 的「JS 组件助手」一层（目标：不让 agent 在注入业务时再手写任何样式，省 token、提单效），仅把**导航从顶栏改为左侧栏分组**。

## 2. 注入契约

### 2.1 构建命令
```bash
python scripts/build-prototype.py --template desktop-v3 --config config.json --out 输出.html
# --template 取值：desktop | desktop-v2 | desktop-v3 | mobile | prd
```

### 2.2 注入标记（模板内成对存在，build 用 replace_between 替换，**生成文件不残留**）
| 标记 | 注入文件 | 说明 |
|:--|:--|:--|
| `<!-- Agent:NAV_START -->` … `<!-- Agent:NAV_END -->` | nav | **业务分组导航项**（注入到「业务工作台」分组 `#navGroupBiz` 内，见 §5） |
| `<!-- Agent:PAGE_START -->` … `<!-- Agent:PAGE_END -->` | pages | 各业务页面（含 `.page[data-page="xxx"]`） |
| `// Agent:DATA_START` … `// Agent:DATA_END` | data | 业务数据（JS，覆盖 `demoData`，含 `list` 数组供数据列表页） |
| `// Agent:EXAMPLES_START` … `// Agent:EXAMPLES_END` | （自动清空） | 模板示例业务，**build 自动清空前禁止手改** |
| `/* Agent:COLOR_START */` … `/* Agent:COLOR_END */` | config.colors | 6 个主色变量（见 §3） |

> 系统管理 5 页 / 6 弹窗 / JS 函数库位于**标记之外**的永久区，build 不覆盖（见 §8）。

### 2.3 主色变量（6 个，build 自动重写，agent 禁止改 CSS 内其它值）
```css
:root{
  --accent: #6366F1;                  /* V3 主色：靛蓝 */
  --accent-hover: #4F46E5;
  --accent-rgb: 99,102,241;
  --accent-bg: rgba(99,102,241,.10);
  --accent-border: rgba(99,102,241,.20);
  --sidebar-active: rgba(99,102,241,.10); /* 侧栏选中背景（复用同名变量名） */
}
```
> `config.json` 的 `colors` 只需给 `--accent` HEX，`build-prototype.py` 的 `auto_accent_rgb` 会自动推导其余 5 个。

> **⚠️ 渐变卡按钮对比度铁律（C-contrast）**：任何叠在 `linear-gradient(...var(--accent)...)` 渐变卡（如 `.rail-welcome` 欢迎卡、`.feedback-card` 反馈卡）上的按钮，**禁止**用 `background:rgba(255,255,255,.xx)` 半透明白底 + 继承白字——不同 `--accent` 下白字对比度会跌破 WCAG AA 4.5:1（靛蓝默认仅约 3.2:1）。必须用「实底白胶囊 + 显式文字色」：`background:#fff;color:color-mix(in srgb,var(--accent),#111827 75%)`（旧浏览器回退 `color:var(--accent)`）+ `box-shadow` 与渐变分离。模板内 `.rw-btn`/`.fb-btn` 已是此写法，**禁止改回幽灵按钮**。

### 2.4 容器 id 契约（被模板 JS 依赖，**禁止删除/重命名**）
`#loginPage` `#app` `#sidebar` `#sidebarNav` `#navGroupBiz` `#navGroupSys`
`#breadcrumbPath` `#breadcrumbSep` `#breadcrumbCurrent` `#topbar` `#userDropdown`
`#appMain` `#contentScroll` `#rightRail` `#dashStats` `#dashRepos` `#dashFiles` `#dashLine` `#dashDonut` `#dashTodo` `#dashTodoTotal` `#railActivity` `#settingsBody`

### 2.5 V3 无项目切换器（D41 铁律，模板已移除）

> **V3 侧栏只有品牌区 + 分组导航，顶部不存在"项目/门店/公司"切换器**（原型 `prototype-desktop-v3.html` 已删除 `.proj-switcher` 组件，模板不渲染该容器）。
> - **禁止**在注入内容中自建项目切换器、门店筛选器、`proj-switcher` 类下拉
> - 平台管理端 = 总后台，不区分门店/分店视角
> - 若业务确实需要按门店/项目过滤（如运营按门店看报表），用**页内筛选区下拉**实现，不做全局项目切换器

### 2.6 低频操作必须进弹窗/二级页（D42 铁律）

> **列表页主视区只放高频信息**。配置类/发布类/低频操作（规则配置、发布公告、参数设置等）**禁止**作为表单卡片常驻在列表上方——要么进**弹窗**（`openModal`），要么进**二级页**（`openDetailPage`），要么用 **tab 切换**。
> - 正确：列表页页头操作按钮（如「发布公告」「规则配置」）→ 点击打开 `openModal` 弹窗表单
> - 错误：表单卡片 + 列表卡片上下堆叠，低频表单占住列表上方空间（用户实测：分账规则配置/发布公告卡在流水/列表上方，体验差）
> - 高频操作（搜索/筛选/导出/重置）留在页内工具栏
> - Toast 统一居中顶部展示（`.toast-container` 已由模板居中，禁止改回右上角）

## 3. 电池内置 JS 助手（核心：注入业务一律先调这些，别手写 HTML/CSS）

| 函数 | 签名 | 返回 | 示例 |
|:--|:--|:--|:--|
| `statCard` / `kpiCard` | `{label,value,trend,dir,icon,color}` | KPI 卡 | `statCard({label:'总用户',value:'1,284',trend:'+12%',dir:'up',icon:'fa-users',color:'blue'})` |
| `dataTable` | `(columns[], rows[][], {emptyText})` | 表格（含空态） | `dataTable(['用户','手机号','状态'],[['张三','138…',statusTag('done')]])` |
| `appItem` | `{name,sub,icon,color,onclick}` | 应用宫格卡 | `appItem({name:'OA系统',sub:'立即访问',icon:'fa-building',color:'#3B82F6'})` |
| `fileListItem` | `{name,meta,icon,color,tag}` | 文件/仓库列表项 | `fileListItem({name:'repo',meta:'main · 2h',icon:'fa-code-branch',color:'#6366F1',tag:'前端'})` |
| `timeline` / `activityTimeline` | `events[{date,items[]}]` 或 groups | 时间轴 | `activityTimeline(demoData.activities)` |
| `progressBar` | `pct` | 进度条 | `progressBar(72)` |
| `tabs` | `items[{label,onclick}], activeIdx` | 标签页 | `tabs([{label:'全部',onclick:'fAll()'}],0)` |
| `miniCalendar` | `{year,month,today,marks}` | 迷你日历 | `miniCalendar({year:2026,month:8,today:3})` |
| `chartBar` | `data[{l,v}], {width,height}` | SVG 柱状图 | `chartBar([{l:'周一',v:120}],{height:160})` |
| `chartLine` | `data[{l,v}], {width,height}` | SVG 折线图（带面积渐变） | `chartLine([{l:'1',v:30},{l:'2',v:55}],{height:160})` |
| `chartDonut` | `segments[{label,v,color}], {size}` | SVG 环形图+图例（容器 flex 居中，`justify-content:center`，图表与图例整体水平居中） | `chartDonut([{label:'待审',v:12,color:'#f59e0b'}])` |

## 4. 注入文件结构

### 4.1 nav（业务分组导航项，注入 `#sidebarNav` 的 `NAV_START/END` 之间）

> 🔴 **多分组铁律（M105）**：NAV_START/END 标记位于 `#sidebarNav` 内（`navGroupBiz` 外），子 Agent **必须按业务模块注入多个 `.nav-group`**，禁止把所有业务页塞进一个"业务工作台"组。分组折叠交互由模板 JS 委托统一绑定，**禁止**在 nav-group-head 上加 `onclick="toggleNavGroup(this)"`（会与委托重复触发）。

**正确（多分组）**：
```html
<div class="nav-group">
  <div class="nav-group-head" role="button" tabindex="0" aria-expanded="true"><span class="group-name">工作台</span><i class="fa-solid fa-chevron-down caret"></i></div>
  <div class="nav-group-body">
    <div class="nav-item active" data-page="dashboard" onclick="switchPage('dashboard')"><i class="fa-solid fa-gauge-high"></i><span class="label">工作台</span></div>
  </div>
</div>
<div class="nav-group">
  <div class="nav-group-head" role="button" tabindex="0" aria-expanded="true"><span class="group-name">车源管理</span><i class="fa-solid fa-car-side caret"></i></div>
  <div class="nav-group-body">
    <div class="nav-item" data-page="cars" onclick="switchPage('cars')"><i class="fa-solid fa-car"></i><span class="label">车源审核</span></div>
    <div class="nav-item" data-page="car-recycle" onclick="switchPage('car-recycle')"><i class="fa-solid fa-box-archive"></i><span class="label">回收车源</span></div>
  </div>
</div>
<div class="nav-group">
  <div class="nav-group-head" role="button" tabindex="0" aria-expanded="true"><span class="group-name">商家管理</span><i class="fa-solid fa-store caret"></i></div>
  <div class="nav-group-body">
    <div class="nav-item" data-page="merchants" onclick="switchPage('merchants')"><i class="fa-solid fa-shop"></i><span class="label">车商审核</span></div>
  </div>
</div>
<!-- 分组「系统设置」由模板永久区提供，勿在 NAV 标记内重复 -->
```
**分组建议**：按业务域分（工作台 / 车源管理 / 商家管理 / 订单管理 / 用户管理…），每个组 1-3 个二级页。**禁止**只有一个"业务工作台"兜底组。
> **V3 无侧栏折叠功能**（用户 2026-08-09 要求移除「收起侧栏」，模板已删 `toggleSidebar`/`.sidebar.collapsed`/`--sidebar-w-collapsed`；D7 检查对 V3 降级跳过）。分组折叠用 `toggleNavGroup(head)`（点击 `.nav-group-head`，`toggleNavGroup`/`setGroupCollapsed`/`.nav-group.collapsed` 保留）。**禁止**重新加回收起侧栏按钮或 `toggleSidebar`。

### 4.2 pages（业务页面，每个 `.page` 必须有 `data-page` 且含切换目标）
```html
<section class="page" data-page="users" style="display:none">
  <div class="page-header"><div><h2>用户管理</h2><p class="page-desc">...</p></div></div>
  <div class="card"><div class="card-header">用户列表</div>
    <div class="card-body" id="userTable"></div>
  </div>
</section>
```
> 页面渲染写在 `biz.js` 的 `init()` 或 `renderAll()` 扩展里。模板 `doLogin()` 优先调业务 `init()`，否则回退 `renderAll()`。

### 4.3 data（覆盖 `demoData`，JS）
```js
var demoData = {
  stats:[...], apps:[...], myApps:[...], docs:[...],
  repos:[...], files:[...], activities:[...], todos:[...],
  list:[ {id:'L001', name:'...', type:'...', status:'done', owner:'...', updateTime:'2026-08-06'}, ... ]  // 数据列表页
};
```

> ⚠️ **手机号/电话脱敏铁律（D36，强制）**：任何含手机号/电话号码的字段（用户/管理员/成员列表等）**必须以脱敏形式存储与渲染**——`13800138001`→`138****8001`、固话 `0571-88886666`→`0571-****6666`。模板已内置 `maskPhone()`，渲染时一律 `maskPhone(m.phone)`；若 data.js 直接写明文 11 位手机号，lint **C1-28** 与 browser-check **B10** 会拦截交付。

### 4.4 biz（追加到最后一个 `</script>` 前）
```js
function init(){ renderUsers(); renderOrders(); }   // 各页面渲染函数
function renderUsers(){ /* 用 dataTable / statCard 等助手渲染 #userTable */ }
```
> 数据列表页 `list-page` 已由模板内置 `renderListPage()` + `demoData.list` + 搜索/筛选/分页/新增/详情，业务只需在 `demoData.list` 提供数据即可，无需重写。

## 6. Lint / Browser 铁律适配（V3 专属）

- **桌面端识别**：`is_desktop_file` 命中规则 `('sidebar' in content and 'switchPage' in content)`——V3 保留 `.sidebar` + `switchPage`，自动识别为桌面端。
- **现代范式降级**：`is_modern_paradigm` = V2 ∨ V3，D9（表数据）/ M47（列表详情）/ M49（弹窗表单）/ C1-7（分页注入）对 V3 同享降级，表格数据由 JS 运行时注入，静态行数检查跳过（运行时由 browser-check B3+ 验证）。
- **模板白名单**：`prototype-desktop-v3.html` 必须加入 `agent-lint.py` 与 `browser-check.py` 的 `is_template_file` 白名单，否则 C1-3（残留标记）/ I1（模板占位按钮）/ C1-4（示例表格）会误判失败（DV17）。
- **C1-8（V3 侧栏分支）**：`agent-lint` 检测到 `nav-group`（侧栏分组）时走 V3 分支——校验「系统设置」分组含 5 个 `data-page` 二级项 + `toggleNavGroup` 函数 + `#page-xxx` 齐全；**模板文件也检查**（防系统管理被误删）。
- **B3+++（browser-check 新增）**：判定 `.nav-group!==null && .topnav-group===null && .nav-parent===null` 时，验证 `.nav-group-head` 点击 `toggleNavGroup` 切换分组展开、以及「系统设置」分组 5 个标准二级菜单可达（V3 无侧栏折叠断言，2026-08-09 移除）。
- **类名覆盖率（C1-6）**：注入 HTML 使用的 class 必须有模板 CSS 定义，优先用模板预置类，禁止自创类名（无样式 = 拦截）。
- **C1-2 内置函数白名单**：`agent-lint` 的 onclick 引用函数检查已把浏览器原生 `alert`/`confirm`/`prompt` 纳入白名单，`onclick="alert('已提交')"` 合法不再误报；但业务按钮仍应优先用 `openModal`/`showToast` 体系，避免裸 `alert`（体验差）。

## 7. 二级页面 / 弹窗 / 表单 决策（同 V1/V2 铁律 M46/M47）
- ≤8 字段、轻量表单/确认/向导 → `openModal(title, html, footerHtml)` 弹窗（footerHtml 防双按钮）。
- >8 字段、含图片/长描述 → `openDetailPage(page, opts)` 二级页面（带面包屑 + 返回 `goBackFromDetail`）。
- 列表行「详情」入口必接 `openDetailPage`；所有操作按钮必须有真实响应，禁止 `showToast` 占位（I6 铁律）。
- **详情页容器（V1/V2/V3 统一范式 D45，模板已内置 `page-xxxDetail` 示例）**：
  - **标题区** `.detail-header`：返回按钮 `<button class="detail-back" onclick="goBackFromDetail()">` + `<div>`（`.detail-title` 可内嵌状态 `<span class="tag" id="xxxStatusTag">`，JS 用 `innerHTML` 填充 + `.detail-sub` 副标题，如"编号 · 时间"）+ `.detail-actions` 操作区（JS 注入按钮）。
  - **内容区** `.detail-cards`（可 `.full` 通栏）> `.detail-card` > `.detail-card-title`（图标 + 分组标题）+ 空容器 `.detail-grid`（**JS 用 `kv(k,v)` 注入 `.detail-item`（`.dl` 标签 / `.dv` 值）**，禁止静态写死字段）/ `.detail-desc`（长文本）/ `.detail-timeline`（时间线，JS 填充 `.tl-item`）。
  - 填充示例：`grid.innerHTML = kv('订单号', it.id) + kv('金额', '¥'+it.amount);`；标题：`title.innerHTML = '订单详情 ' + tagFrom(ORDER_STATUS, it.status);`；副标题：`sub.textContent = it.id + ' · 下单 ' + it.time;`
  - 正文样式 `.detail-*` 与 `kv()` 全部模板预置，**禁止自创详情页类名**。
  - 打开：`openDetailPage('xxxDetail', {back:'来源页data-page', path:'面包屑前缀 /', title:'标题'})`；返回按钮 `onclick="goBackFromDetail()"`。

## 9. UI 细节规范（2026-08-08 补充，模板内置）

### 9.1 翻页器布局：共 X 条左置 / 翻页按钮右置
- 模板 `pagedRender()` 渲染的分页器（`.table-footer`）结构为：左侧 `.pages-total`（「共 N 条」）+ 右侧 `.pages`（页码按钮组）。
- **铁律**：「共 X 条」必须在左、翻页按钮在右，二者用 `justify-content:space-between` 撑开；browser-check（B3+ 衍生）断言 `.pages-total` 在 `.pages` **之前**（`compareDocumentPosition` 判定），倒置即判失败。
- 业务注入分页器时禁止把总数挪到右侧或按钮挪到左侧。

### 9.2 列表操作列等距对齐
- 字典配置 / 用户列表等表格的操作列（编辑/删除按钮）使用 `display:inline-flex; gap:8px` 等距排列，按钮间间距固定，避免长短不齐。
- 操作按钮统一用 `.btn .btn-sm .btn-default`（编辑）/ `.btn .btn-sm .btn-danger`（删除），**禁止**内联 `style` 写死 margin/padding，交由模板 `.btn-sm` 体系统一样式。

### 9.3 登录卡布局（全屏背景图 + 居中白卡，重构版）
- 结构：`.login-page`（全屏 flex 居中）> `.login-bg`（`<img>` 全屏铺满 `object-fit:cover`）+ `.login-bg-mask`（半透明渐变遮罩 `backdrop-filter:blur`）+ `.login-card`（400px 居中白卡，`backdrop-filter` 毛玻璃）。
- 白卡内容自上而下：`.login-head`（仅 `.login-brand` 品牌标识——`.login-brand-icon` logo 居上、`.login-brand-name` 文字居下、整体水平居中，已移除 `.login-title`/`.login-sub` 欢迎语）→ `.login-form`（账号/密码/验证码 `.input-wrap` 带 Font Awesome 图标 + `.login-opt` 记住/忘记）→ `.login-btn`。
- **背景图保留铁律**：`.login-bg` 的 `<img>` 与 `.login-bg-mask` 必须保留，不可移除背景图改为纯色底（用户明确要求保留背景图）。

### 9.3a 登录页复用铁律（D37 强制，禁止重复产出）
- **`#loginPage` 由模板唯一提供，业务注入内容禁止再写任何 id="loginPage" / class="login-page" 的登录页**（含 `<section>`/`<div>` 形式）。
- 登录页所有可改内容通过模板占位符注入：项目名 `{{项目名称}}`、管理员 `{{管理员姓名}}` 等，不要重建整个登录卡。
- 违反后果（D37 实测事故）：注入区重复写 `<section id="loginPage">`（position:fixed + z-index:9999），`doLogin()` 只隐藏模板的 `<div id="loginPage">`，第二个 section 永远遮住 app → 登录"假失败"（dashboard 已 active 但视觉上看不见）。lint **C1-29 重复 id** 与 browser-check **B11 顶层遮罩** 双重拦截，构建即失败。

### 9.4 找回密码轻量提示（禁止 showToast / 大弹窗占位）
- 「忘记密码？」按钮 `onclick` 调 `openForgotPwd()`（**禁止** `onclick="showToast('演示环境暂不支持...')"` 占位——会触发 I5 伪功能按钮 + Q9 showToast 残留双拦截；**也禁止**用 `openModal` 大弹窗承载，过度设计）。
- `openForgotPwd()` 显示**锚定在「忘记密码？」按钮正下方的黑色浮层提示**（非屏幕底部居中条）：用 `document.querySelector('.login-forgot').getBoundingClientRect()` 量出按钮位置，`#forgotHint` `.forgot-hint` 设 `top=按钮底边+10px`、`left=按钮左缘`、`background:#1f2937` 黑底白字、显示「请联系管理员重置密码」；`.forgot-hint::before` 画朝上的小黑三角（`border-bottom:6px solid #1f2937`，`top:-6px;left:16px`）连接按钮，视觉上"从按钮弹出"。
- 交互：① **2 秒自动消失**——`setTimeout(hideForgotHint,2000)`，重开时 `clearTimeout(window.__fhTimer)` 防叠加；② **点击页面任意其他位置（含提示条本身）即消失**——`openForgotPwd` 用 `setTimeout(0)` 在当次点击派发完后再挂 `document` 捕获监听，避免自身点击立即关闭；`hideForgotHint` 同时清除计时器与监听。
- 模板已内置 `openForgotPwd`/`hideForgotHint` 两个函数 + `#forgotHint` 元素 + 对应 CSS（含 `::before` 三角），业务无需重复定义。
