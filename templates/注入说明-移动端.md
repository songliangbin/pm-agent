### 🔴 禁止默认登录页铁律（M79：移动端原型默认不生成登录页）

**背景**：用户明确要求——移动端原型**默认不要有登录页**，直接进入业务首页（用户端进 `page-home`、商家端进 `page-workbench` 等）。历史项目（天天买菜）子 Agent 习惯性把微信登录/账号登录页作为第一个 `page active`，导致首屏是登录页，违反用户偏好。

**铁律**：
1. **移动端 main.html 禁止生成登录页**（`page-login` / 微信一键登录 / 账号密码登录等）作为默认首屏或任何默认展示页面。
2. **默认 active 必须指向业务首页**（与 nav.html 的默认 active Tab 对应，如 home / workbench），禁止用登录页占 active。
3. **禁止生成 `wechatLogin()` / `merchantLogin()` / `merchantLogout()` 等登录态函数**，除非用户在需求里**显式要求**登录页（此时才允许，且需保证登录后正确切换到业务首页）。
4. 若用户未要求登录页，"我的"页底部的"退出登录"按钮**禁止出现**（无登录态概念）；如需保留快速导航，改用 `switchTab('workbench')` 等返回首页类入口。
5. 违反本条 = 用户验收不通过，需在交付前自查 main.html 首块是否为业务首页（非登录页）。

## AI 助手页面规范（M61 铁律：AI 助手做成二级子页面，入口保留在底部导航 Tab）

**背景**：历史教训——AI 助手作为主 Tab 时，底部的聊天发送栏（input + 发送按钮）与悬浮导航栏产生视觉冲突和操作干扰，体验差。用户明确要求：**AI 助手入口保留在底部导航中，点击时跳转到二级页面**，禁止在页面内新增悬浮按钮。

**铁律**：
1. **AI 助手/智能客服/聊天机器人**等功能的**页面本体必须是二级子页面**（`sub-page` 结构，含返回按钮），禁止做成主 Tab 页内容
2. 子页面结构：`.sub-page-header`（返回按钮 + 标题"AI 助手"）+ `.sub-page-body`（聊天内容区，`flex:1;overflow-y:auto`）+ `.detail-bar`（底部输入栏：input + 发送按钮，固定底部）
3. **入口保留在底部导航 Tab 中**：底部导航仍保留 AI Tab（5 Tab 结构不变），但 AI Tab 的 onclick 用 `onclick="openSubPage('sub-ai')"`（**禁止用 switchTab('ai')**，因为 AI 是二级页面而非主 Tab 页）；打开二级页面时底部导航自动隐藏，不与发送栏冲突
4. **禁止在页面内新增悬浮按钮**（如 `.ai-float-btn`）作为 AI 入口
5. `renderChat()` 的滚动目标改为 `document.getElementById('chatList')`（子页面内的聊天列表元素），不再滚动 `.content`
6. `tabTitles` 中不包含 AI 条目（switchTab 不会切到 AI）

## 按钮文字铁律（W4/W5/W6，UI设计系统 1.7 节，生成时必查）

> **绝对常识**：按钮文字永不换行（"已下订 · 待支付"永远一行）。文字放不下 → 拉长按钮/缩短文案。

1. **`.btn` 已内置 `white-space:nowrap`**（模板保证），**禁止**内联覆盖改回可换行。
2. **按钮宽度**：`.detail-bar .btn{flex:0 0 auto}`（按内容宽，主按钮长是正常）——**禁止** `flex:1` 把按钮压窄导致文字换行（用户实测 M103）。
3. **按钮文案要短**：主按钮 ≤6 字、次要 ≤4 字；状态变化时（如下订后）按钮文案**变短**（"已下订"），长状态用按钮旁 tag 或下方说明，**不把长状态塞进按钮**。

## 组件结构契约（M82+ 铁律：组件内部结构必须按模板约定，违反=右箭头不右对齐/排版错乱）

> **背景**：历史教训——`.mine-menu-item` 模板只对 `<i>last-child` 做 `margin-left:auto` 推右，子 Agent 用 `<svg>` 箭头导致「文字在左、箭头贴文字、未推到行尾」。模板现已兼容 `i`/`svg` 两种箭头，但**结构必须按以下契约写**，禁止自由发挥。

**通用规则**：菜单/列表行（`.mine-menu-item` / `.list-item` / `.mine-order-entry`）一律是 **「内容 + 右侧元素」两段式**：
1. 内容段：文字用 `<span>` 包裹
2. 右侧元素（箭头/标签/徽章）必须是该行**最后一个子元素**（`svg` 或 `i` 或 `.tag`），模板自动推右
3. 文字不包 span、或右侧元素不是最后一个子元素 = 箭头不右对齐 = lint M83 拦截

**各组件结构示例**：

```html
<!-- .mine-menu-item：<span>文字</span> + <svg>右箭头</svg>（两段式） -->
<div class="mine-menu-item" onclick="openSubPage('sub-about')">
  <span>关于天天买菜</span>
  <svg width="16" height="16" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.6" stroke-linecap="round" stroke-linejoin="round"><path d="M9 6l6 6-6 6"/></svg>
</div>

<!-- .list-item：<span>主内容</span> + <span>辅助/右侧</span>（两段式，首段 flex:1） -->
<div class="list-item" onclick="selectAddress(1)">
  <span>张* *<br><span style="color:var(--text-3);font-size:12px;">幸福路12号</span></span>
  <span class="tag tag-ok">默认</span>
</div>

<!-- .mine-order-entry：<span>标题</span> + 右侧箭头 -->
<div class="mine-order-entry" onclick="switchTab('orders')">
  <span>我的订单</span>
  <svg width="16" height="16" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.6" stroke-linecap="round" stroke-linejoin="round"><path d="M9 6l6 6-6 6"/></svg>
</div>
```

**禁止行为**：
1. 文字裸写不包 `<span>`（如 `.mine-menu-item` 直接写文字）
2. 箭头/标签写在中间、后面还有内容（右侧元素必须是最后一个）
3. 用内联 `style="display:flex;justify-content:space-between"` 手写菜单行排版（**排版走组件类，禁止内联覆盖**）

## 横向滚动规范（M41 铁律：禁止可见滚动条）

移动端原型在浏览器中打开时，**一切滚动条必须隐藏**（横向和纵向均不可见）。

- 纵向滚动（页面/内容区）：模板已通过 `::-webkit-scrollbar{display:none}` + `scrollbar-width:none` 隐藏，鼠标滚轮正常滚动
- 横向滚动（分类选项/标签栏等）：在容器上**同时加 `drag-scroll` 类**，模板自动隐藏滚动条并启用鼠标拖拽浏览
- 使用方式：`<div class="shop-cats drag-scroll">` 或 `<div class="sub-cats drag-scroll">`
- `initDragScroll()` 由模板 DOMContentLoaded 自动调用，子 Agent 禁止重复定义
- **禁止**在 CSS 中使用 `overflow:scroll` 或 `overflow-x:scroll`（会显示滚动条），必须用 `overflow-x:auto`
- **禁止内联 `overflow-y:auto` / `overflow-y:scroll` / `max-height` 组合**（D46 防护）：弹层/内容区禁止自己滚，内容由模板滚动容器统一处理。内联滚动条 = lint C1-32 拦截

## 首页入口映射铁律（D43 防护，违反 = C1-34/C1-35 fail）

> 依据 `standards/移动端产品逻辑规范.md`（常识库）。**每个入口必须指向语义对应的目标页**，禁止全部入口指同一个列表函数。

| 入口 | 目标页 | 说明 |
|:--|:--|:--|
| 搜索框 `.home-search` | `sub-search` 搜索页 | 含 `<input` + 热词/历史 |
| Banner `.home-banner` | `sub-activity*` 活动专题页 | 含倒计时 + 活动墙 + 规则；**多个 banner 必须指向不同页面**（L6） |
| 金刚区类目 | 对应类目列表页 | 每个类目指向自己的列表（本来就不同） |
| 金刚区功能位（优惠券/订单/客服） | 对应功能页 | 券包页/订单页/聊天页 |
| 营销卡 `.promo-card`/秒杀/领券 | 对应专题页 | 秒杀页/领券中心 |
| 商品/服务卡 | `sub-service-detail` 详情页 | 头图+参数+评价+底部操作栏 |
| 门店/商家卡 | `sub-store-detail` 门店详情页 | 门店头+服务列表+评价 |

**L6 多样性铁律**：同一入口组内（banner 组/金刚区/营销卡组），**每个入口必须指向不同的目标页**。示例：banner1→活动A、banner2→服务详情、banner3→活动B。同组目标去重后数量 < 入口数 = C1-35 fail。

**若目标页不存在 → 必须新建该类型 sub-page**（照本章「标准二级页骨架」建），禁止降级指向别的页面。

## 弹层规范（D44/D45 防护，违反 = C1-33/B13 fail）

1. **sheet 必须放进 `#sheetMask` 容器内**：模板已内置 `<div class="sheet-mask" id="sheetMask">`，新增弹层时把 `.sheet` 块**放进 mask 内**（如 `<div class="sheet" id="sheet-coupon">` 置于 mask 内），**禁止平铺独立 `.sheet`**（C1-33 拦截）
2. **弹层内容禁滚动条**：sheet/modal 内部禁止内联 `overflow-y:auto`（C1-32 拦截）
3. **跳转前必须关弹层**：任何 `openSubPage()` 跳转前必须先 `closeSheet()` / `closeModal()`（B13 拦截"弹层残留盖在下一页面前"）
4. sheet 已由模板置于 nav-wrapper 之上（z-index 161 > 150），**禁止把 sheet 的 z-index 改小或改回 absolute 到滚动容器内**

### 子页面位置铁律（M63：sub-page 必须在 .content 容器之外）

**背景**：历史教训——sub-page 若被放进主页面 `.content` 容器内部，`.sub-page{position:absolute;inset:0}` 会相对 `.content`（其 top 已偏移 `--status-h + --topbar-h`）定位，导致二级页面顶部出现约 100px 空白、导航栏位置错误、微信胶囊等上层元素在空白区残留，视觉像"带着其他页面的内容"。

**铁律**：
1. 所有 `sub-page` **必须放在 `.content` 容器之外**（即 `.content` 闭合 `</div>` 之后、`.nav-wrapper` 之后的区域，模板 Agent:PAGE_START/PAGE_END 注释之间），作为 `.phone-screen` 的直接子元素
2. **禁止**把 `.sub-page` 放进主 Tab 页（`.page`）内部或 `.content` 内
3. 若把某功能从主 Tab 页改造为二级页面，必须**移动整个 sub-page 块到 .content 外**，不能原地替换
4. 验证：`sub-page` 的 DOM 位置应在 `nav-wrapper` 之后；`.content` 内只允许 `.page` 主页面

## 换行分层铁律（W1/W2/W3，UI设计系统 1.6 节，生成时逐条对照）

> 用户实测教训：**不能一刀切**——"¥15.8万"折成两行（数字和单位断开）是错的；但把整行 `nowrap` 硬撑导致**溢出卡片**同样是错的。真人 UI 的做法是**分三层 + 布局变通**：

| 原则 | 正确做法 | 错误做法 |
|:--|:--|:--|
| **W1 量值内部不换行** | JS 用 `&nbsp;`：`'¥'+c.price+'&nbsp;万'`、`c.mileage+'&nbsp;万公里'`、`c.year+'&nbsp;年上牌'` | `+c.price+'万'` 裸拼接（lint M101 拦截）|
| **W2 信息单元之间可换行** | 年份/里程/变速箱等短单元各自 `nowrap`，容器 `flex-wrap:wrap`，放不下在**单元之间**换行（`.tag-row` 类已内置）| 把整串锁死 `nowrap` 溢出卡片（lint M102 预警）|
| **W3 长文本正常换行** | 公告/详情描述/简介等段落不设 nowrap，自然折行 | 给长文本加 nowrap 单行截断 |

**标准卡片布局（信息展示类，如商品/车源/订单卡）**：
```
[主图/图标区]
标题（1-2行截断，正常换行）
¥15.8万          ← 价格独行（product-price，nowrap 安全因价格短）
2021款 · 3.2万公里 · 自动  ← 元信息：用 .tag-row（flex-wrap），单元间可换行
```
- **价格独行**：核心信息，独占一行（`.product-meta` 已改 `flex-direction:column`），禁止和元信息 `space-between` 硬挤
- **元信息用 `.tag-row`**：`<div class="tag-row"><span>2021款</span><span>3.2&nbsp;万公里</span><span>自动</span></div>`——每个 span nowrap，容器 flex-wrap
- **量值元素 CSS**：`.product-price/.detail-price` 自带 nowrap（价格短安全）；`.product-sales` 已改 `white-space:normal`（可换行），**禁止改回 nowrap**

## 元素可点性铁律（M111 防护：禁止"可点样式 + 无交互"死按钮）

> **背景（茶叶商城事故）**：工作台统计卡（`.work-stat`）/待办（`.todo-item`）/菜单项（`.mine-menu-item`）使用了可点样式（`cursor:pointer`）但未绑定 onclick，用户点击无反应。生成时若跳过浏览器断言，B6 运行时检查无法兜底，死按钮漏网交付。

**铁律（违反 = lint M111 静态拦截 + browser-check B6 运行时拦截，双保险）**：

| 元素 | 正确做法 | 反面案例 |
|:--|:--|:--|
| 统计卡 `.work-stat` | **必须可点**跳转对应列表/页面（今日订单→订单页、待发货→待发货筛选、销售额→统计页） | 无 onclick 的纯展示统计卡 ❌ |
| 待办 `.todo-item` | **必须可点**进详情/处理（订单待办→订单详情、审核待办→审核页、提现待办→提现页） | 审核类待办无 onclick ❌ |
| 菜单项 `.mine-menu-item` | 必须绑定 onclick；联系信息（客服热线/邮箱/网址）用 `tel:`/`mailto:` 链接或复制到剪贴板 | 用 menu-item 类做纯展示无交互 ❌ |
| 分类 Tab `.shop-cat`/`.sub-cat` | 非激活 Tab 必须有 onclick 切换 | 非激活 Tab 无 onclick ❌（激活 Tab 可无） |
| 轮播指示器 `.banner-dot` | 可绑定点击切换（增强项，非必选） | 无 onclick 不判失败 |

**判定原则**：
1. 任何元素若 CSS 有 `cursor:pointer` 或属于上述可点语义类，**必须绑定 onclick**
2. 无法实现交互的元素：**去掉可点样式**（删除 `cursor:pointer` 或改用非可点类，如纯展示信息用 `.list-item` 或普通 div）
3. 纯展示信息（客服电话/邮箱等）若不做 tel:/mailto:，**禁止套用 `.mine-menu-item` 可点类**

## 卡片/功能区布局完整性铁律（M113 防护：禁止孤卡留白）

> **背景（茶叶商城事故）**：`.work-stats` 是 3 列网格，工作台塞了 4 个统计卡（今日订单/今日销售额/待发货/总收入）→ 3+1，第四行只剩「总收入」一个孤卡、右侧大片留白，视觉不协调。

**铁律（违反 = lint M113 静态拦截 + browser-check B21 运行时拦截，双保险）**：

1. **网格容器卡片数必须与列数整除**：`.work-stats`=3 列（3/6/9 卡）、`.work-quick`=4 列（4/8 卡）、`.home-cats`=5 列（5/10 卡）。**禁止** 4 卡塞 3 列、3 卡塞 4 列这类"孤卡留白"
2. **卡片数不整除时的两种标准解法**：
   - **大卡 + 小卡组合**：总览值（如「总收入」）用跨行大卡 `.work-stat-main`（`grid-column:1/-1` 占满整行，模板已提供样式），下方 3 个小卡填满一行 → `1 大卡 + 3 小卡`
   - **增补或调整数量**：补到列数整数倍（如 3 列放 6 卡），或用内联 `style="grid-template-columns:repeat(4,1fr)"` 改成 4 列放 4 卡（4 卡正好一行）
3. **功能区同样适用**：快捷入口/金刚区/服务宫格等网格功能区，入口数量必须与网格列数匹配，禁止末行孤项
4. **大卡内禁止嵌套可点类小卡**：`.work-stat-main` 是一个完整卡片，直接放 `.work-stat-num`/`.work-stat-lbl`，不要在里面再包 `.work-stat`

## 白字白底/渐变背景铁律（M114 防护：禁止白字配白底）

> **背景（茶叶商城事故）**：工作台大卡 `.work-stat-main` 渐变写成 `linear-gradient(135deg,var(--brand),var(--brand-hover))`，但 `--brand-hover` 变量未定义——整个 background 声明被判无效丢弃，卡片回退白底，文字却是 `#fff`，白字白底根本看不清。

**铁律（违反 = lint M114 静态拦截 + browser-check B22 运行时拦截，双保险）**：

1. **白字渐变/纯色卡**（`color:#fff`）背景**必须保证有效且深色**：渐变两个端点都必须是已定义变量或硬编码深色（如 `var(--brand),var(--brand-light)` 或 `var(--brand),#FF8A66`），禁止引用未定义变量（如 `--brand-hover`）
2. **引用 CSS 变量前先确认它已定义**：模板 `:root` 已定义 `--brand/--brand-light/--brand-bg/--brand-rgb/--accent/--accent-hover/--accent-bg/--accent-rgb` 等，只准用这些；拿不准就用硬编码颜色兜底
3. **需要兜底写法**：`var(--xxx, 兜底值)` 带 fallback 是合法且安全的
4. **白字必须配深色/渐变背景，深色字必须配浅色背景**：任何"白字 + 白底"、"深字 + 深底"都是不可交付的低级错误

## 启动渲染铁律（M115 防护：所有页面必须由 init() 统一渲染，禁止渲染函数"定义不执行"）

> **背景（茶叶商城事故）**：注入端定义了 `init()` 与 10+ 个 render 函数（renderCart/renderOrders/renderNewArrival/renderCategorySidebar…），但模板启动只调 `renderHomeProducts`，`init()` 从未执行 → 分类/购物车/订单/新品页**全部空白**；而「我的订单」入口因直接调 `goOrderTab→renderOrders` 反而有数据——数据都在，页面却渲染不出，这种交付是不可接受的。

**铁律（违反 = lint M115 静态拦截 + browser-check B23 运行时拦截，双保险）**：

1. **所有页面初始渲染统一收进 `init()`**：首页/分类/购物车/订单/收藏/地址/搜索热词/新品等，在 `init()` 里逐项调用对应 render 函数。模板 DOMContentLoaded 会自动调用 `init()`
2. **多 Tab/多页面结构（≥2 个 `.page` 容器）必须定义 `init()`**，禁止依赖模板回退的 `renderHomeProducts`（那只兜底首页）
3. **禁止"渲染函数定义但无调用"**：每个 `renderXxx()` 都必须在 `init()`（或业务函数）中真正被调用；`init()` 不得是空壳（必须实际调用 ≥2 个 render）
4. **Tab 切换只做显隐，不做渲染**：渲染只发生在 `init()` 和数据变更后；切换 Tab 时若对应容器为空 = 渲染缺失，lint/browser-check 直接打回

## 购物车标准组件铁律（M116 防护：购物车必须复用标准组件，禁止另起炉灶）

## 筛选标签栏 sticky 铁律（M117 防护：筛选栏必须固定在顶部，禁止随内容滚动）

> **背景（茶叶商城事故）**：订单页「全部/待支付/待发货」筛选栏未 sticky，页面下滑时筛选栏跟着列表一起滚出视口（用户原话：这是基本常识）。

**铁律（违反 = lint M117 静态拦截 + browser-check B24 运行时拦截，双保险）**：

1. **订单/状态/筛选类标签栏必须 `position:sticky` 固定在页面顶部**，不随列表内容滚动
2. **复用模板 `.orders-tabs` 类**（已内置 `position:sticky;top:8px`），禁止自定义非 sticky 的筛选容器（类名以 `tabs` 结尾的自定义类，lint 强制要求 CSS 含 sticky）
3. **sticky 的 `top` 必须等于 `.page-content` 的 padding-top（8px）**：`.content` 视口顶部已在 top-bar 之下，若误设 `top:calc(status-h + topbar-h)` 会导致筛选栏初始即被 sticky 下推、与首条内容重叠
4. **禁止在筛选容器祖先上使用保留 transform 的入场动画**（动画结束态必须 `transform:none`，模板 pageEnter 已合规）

## 底部操作栏响应式铁律（M118 防护：按钮必须伸缩填满，禁止右侧留白）

> **背景（茶叶商城事故）**：商品详情页底部「加入购物车/立即购买」两按钮后大片留白——模板旧规则 `.detail-bar .btn{flex:0 0 auto}` 按钮按内容宽度排布、不伸缩填满。行业常规（微信小程序详情页/CommerceActionBar）：底部栏**主行为按钮宽度加倍（约 2:1）、辅按钮等分，多按钮必须填满整行**；单按钮自适应居中。

**标准布局（模板 `prototype-mobile.html` 已内置，禁止覆盖）**：

| 场景 | 布局规则 |
|:--|:--|
| 1 个按钮 | 自适应宽度 + 居中（`flex:0 0 auto` + 左右 margin auto） |
| 2 个按钮（辅+主） | 辅按钮 `flex:1`（约 1/3）、主按钮 `.btn-primary` `flex:2`（约 2/3），填满整行 |
| 2 个同类型按钮 | 均 `flex:1` 平分填满 |
| 3~4 个按钮（多个辅+一个主） | 辅按钮等分、主按钮 `flex:2` 最宽，空间不足时辅按钮先收缩（`flex:1 3 0`） |
| 动态注入按钮（如订单详情操作栏） | 直接子元素 `<button class="btn ...">` 即自动响应式 |

**铁律（违反 = lint M118 静态拦截 + browser-check B25 运行时拦截，双保险）**：

1. **底部操作栏按钮禁止设 `flex:0 0 auto` / `flex:none`**（不伸缩 → 右侧留白，不可交付）
2. **多按钮必须填满整行**：最后一个按钮右缘须贴近操作栏右缘（留白 ≤3px）
3. **主按钮（`.btn-primary`）必须更宽**（`flex:2`），辅按钮（`.btn-default` 等）较窄（`flex:1`）
4. **单按钮必须居中**，禁止靠左或靠右
5. **禁止自定义 `.detail-bar` 按钮样式覆盖模板响应式规则**；如确需自建，必须含 `flex` 伸缩

## 移动端业务交互真实化铁律（M53 防护：禁止假按钮，关键业务必须真实状态流转）

**背景**：历史教训——用户端原型曾把聊天发送/订单操作/发布/提现/评价全部做成仅 Toast 提示的假按钮。以下关键业务**必须真实函数化**（状态变化 + 界面重渲染），禁止用 `doAction('提示')` 敷衍：

| 业务 | 必须实现的真实函数 | 行为要求 |
|:--|:--|:--|
| 聊天 | `sendChatMsg()` | 读取输入框 → 追加气泡到聊天流 → 清空输入框 |
| 订单-买家 | `payOrder(id)` `cancelOrder(id)` `confirmReceive(id)` `applyRefund(id)` `repurchase(id)` | 改状态 + 重建订单列表 + Toast |
| 订单-卖家 | `shipOrder(id)`（生成物流单号）`confirmMeetup(id)` `refundOrder(id,action)` `relistProduct(id)` | 同上 |
| 发布商品 | `submitPublish()` | 标题/售价必填校验 → push 到数据 → 刷新"我的发布" |
| 钱包 | `withdraw()` | 扣减余额 + 追加明细 + 界面同步 |
| 评价 | `submitReview()` | 星级校验 → 订单转已评价 |
| 收藏 | `toggleFavorite()` | 图标/文案/状态切换 |
| 地址 | `addAddress()` `editAddress()` `deleteAddress()` `setDefaultAddress()` | 数据增删改 + 列表重建 |
| 我的发布 | `renderMyPublish()` `relistMyProduct(id)` | 数据驱动重建列表 |

**硬性要求**：
1. 列表重建统一走**数据驱动**：`renderXxx()` 从数据源（orderData/productData 等）重建 innerHTML，禁止手工改单个 DOM
2. 按钮 onclick **禁止**绑定 `doAction(...)` 提示语（仅允许 Toast 反馈用），必须调真实业务函数
3. 数据源与展示一致：新增/修改数据后必须重新渲染
4. Lint M53 白名单强校验：关键业务按钮若仍绑 doAction 直接判失败打回


## 移动端 UI 规范铁律（M54/M55/M56 防护：零滚动条/蒙版隐藏/底部固定栏/导航双模式）

**背景**：历史教训——分类入口被内联样式改成横向滚动条且文字换行；二级页面残留首页渐变蒙版；发布/聊天按钮不固定底部；发布凸起按钮被容器压缩变形；悬浮导航卡片圆角被改成 24px 且高度被撑到 56px。以下规范**必须遵守**：

| 规范 | 要求 |
|:--|:--|
| 零滚动条 | 一切滚动条隐藏（模板已内置 `scrollbar-width:none` + `::-webkit-scrollbar{display:none}`），禁止内联 `overflow:scroll` |
| 分类宫格 | `.home-cats` **必须用模板 5 列宫格**（grid 5 列），禁止加内联 `style="display:flex;overflow-x:auto"` 覆盖（会导致滚动条+换行+拥挤）；分类 ≤ 8 个自动 5+3 两行 |
| 文字不换行 | `.home-cat span` 已设 `white-space:nowrap`，分类名/标签不得折行 |
| 商品图SVG | 商品卡片图区**必须手绘内联 SVG 占位图**（台灯画台灯、相机画相机、平板画平板，stroke 白色线条风格 `viewBox="0 0 24 24"` + `width/height:52`），**禁止 `<i class="fa-solid">` 占位**（依赖 CDN 字体且图区无高度会塌陷）。**图区必须固定高度 `height:110px` + `display:flex;align-items:center;justify-content:center`**（否则绝对定位图标错位压住标题），渐变底色 + 居中 SVG + 学校 tag（absolute 左上） |
| 二级页蒙版 | 打开二级页面（`openSubPage`）时导航渐变蒙版必须隐藏（模板已内置，禁止删除 `.nav-mask` hide 逻辑） |
| 底部固定栏 | 发布/聊天/钱包/详情等二级页面底部操作区必须用 `.detail-bar`（模板已设 absolute 固定底部），body 加 `padding-bottom:96px` 防遮挡 |
| 导航双模式 | `.bottom-nav` **固定 `height:52px` + `border-radius:999px` 胶囊形**（M56，禁止改回 24px 圆角 / 56px 高）。**模式二选一**：`nav-plain` 常规（5 tab 等高无凸起）或 `nav-fab` 中间凸起（publish tab 用 `<div class="nav-tab-icon fab-icon">` **44px 圆形凸出** + label 加 `fab-label`）。**fab-icon 内 SVG 图标 `width/height:18`**（44px 圆内 18px 图标比例最佳）。发布 tab 禁止 `min-height>44px`（会撑高卡片），`.nav-tab` 保持 `height:auto` 内容自适应（避免 flex 压缩压扁圆形按钮） |
| 标题栏联动 | `switchTab` 自动更新顶部标题（模板已内置 tabTitles） |
| 数据驱动 | 商品/订单等列表用数据（productData/orderData）渲染（renderXxx 函数），禁止硬编码导致数据与界面脱节 |
| 提交按钮固定 | **所有含提交/发布/确认动作的二级页必须有 `.detail-bar` 固定底部操作区**（学生认证/发布/评价/设置等），body 加 `padding-bottom:96px` 防遮挡；禁止把主按钮放在 body 末尾随内容滚动 |
| Tab 激活态 | 分段 Tab 用 `.order-tab` / `.order-tab.active`（CSS 已内置品牌色胶囊+白字），**禁止在 HTML 里内联 `color:#xxx;border-bottom` 覆盖激活态**（会造成背景块与文字颜色不匹配） |
| Tab 容器 | Tab 容器用浅灰底分段控件：`style="display:flex;gap:6px;padding:10px 12px;background:#F3F4F6;margin:10px 12px;border-radius:14px"` |

**硬性要求**：
1. 禁止用内联样式覆盖模板组件的核心布局（宫格/导航/固定栏）
2. 二级页面必须有固定的底部操作区（.detail-bar）
3. Lint M54 白名单强校验：宫格被内联覆盖 / detail-bar 不固定 / 蒙版无隐藏逻辑 直接判失败
