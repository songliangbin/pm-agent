# 注入说明 — 桌面端 V2「企业驾驶舱 (Enterprise Cockpit) — 顶栏外壳 + 内容全宽 + 右栏系统通知」

> 配套模板：`templates/prototype-desktop-v2.html`（电池内置设计系统 + JS 组件助手）
> 适用：**能源 / 制造 / 工业互联网 / 央国企 / 集团管控**类项目——想要「顶部横向唯一主导航 + 内容全宽 + 右栏系统通知（仅首页）」的驾驶舱观感，凸显「管理驾驶、层级分明、信息穿透」。
> 不适用：① 极重后台（超复杂左树右表、深度权限树编辑）→ 选 V1（`prototype-desktop.html`）；② 想要「GitLab/Coding 式左侧栏 + 顶部轻栏」现代仪表盘 → 选 V3（`prototype-desktop-v3.html`）。
>
> ⚠️ **V2 来源与铁律（2026-08-08 重建）**：本模板依据「企业驾驶舱」类参考设计重建，关键事实由像素测量 + GLM-4V 分区识别双重确认：
> 1. **顶栏是「唯一」导航**——参考图**没有**左侧栏。原 V2 错误地在顶部菜单之外又加了一根左侧菜单（菜单重复），属低级错误，**已彻底删除左栏**。
> 2. **右栏是「待办事项」（v5.41 统一终态）**——右栏内容为 `demoData.todos` 渲染的待办列表（`renderRail()` 填充 `#todoList`），仅首页显示。⚠️ 历史演变备注：早期版本曾按参考图做成「系统通知」，模板终态已回归「待办事项」并经 PM 确认锁定；若你读到旧文档/旧项目产物中出现「右栏系统通知 / #notiList / demoData.notis」字样，一律以本说明与当前模板为准，**禁止**回改成通知语义。
> 3. 配色以测量为准：主色 `#0083FF`、顶栏底 `#CFE9FF`、页面中心 `#F9FBFE`、全局底 `#F5F8FC`。
>
> ⚠️ **V2 已标配「系统管理」**：模板永久区内置「系统管理」入口（顶栏「系统管理」区段 → `#page-settings`，以及顶栏「更多」区段 → `#page-org`），含 5 个标准二级子页（我的组织 / 角色权限 / 菜单配置 / 字典配置 / 操作日志）+ 6 弹窗 + 全套 JS 函数，**与 V1/V3 功能对齐**。详见 §8。

## 4. 注入文件结构

### 4.1 导航（**V2 数据驱动，顶栏唯一，无左栏，不注入 HTML**）
V2 的顶栏区段由模板 JS 的 `TOP_SECTIONS` 对象驱动。**定制导航产出 `navjs` 注入文件**（v5.41 起 build 支持；config 配 `"navjs"` 键指向文件路径），其内容即下述完整声明——build 将整块替换进模板的 `// Agent:NAVJS_START/END` 标记之间并剥离标记：
```js
var MAX_TOPNAV = 8;            // V2 顶栏最多 8 个槽位（含「更多」）。超出的一级菜单自动收入「更多」面板
var TOP_SECTIONS = [           // 顶栏横向唯一主导航（数据驱动，renderTopNav 渲染，无左栏）
  {key:'home',  label:'首页',         icon:'fa-house',    page:'dashboard'},
  {key:'svc',   label:'服务管理',      icon:'fa-spa',      page:'projects',
   children:[
     {label:'服务项目', icon:'fa-spa',        page:'projects'},
     {label:'项目分类', icon:'fa-tags',       page:'categories'}
   ]},
  {key:'tech',  label:'技师管理',      icon:'fa-user-gear',page:'techAudit',
   children:[
     {label:'技师审核', icon:'fa-user-check', page:'techAudit'},
     {label:'技师列表', icon:'fa-users',      page:'techs'}
   ]},
  {key:'trade', label:'交易管理',      icon:'fa-coins',    page:'orders',
   children:[
     {label:'订单列表', icon:'fa-receipt',    page:'orders'},
     {label:'交易流水', icon:'fa-arrow-right-arrow-left', page:'transactions'},
     {label:'提现审核', icon:'fa-money-bill-wave', page:'withdrawals'},
     {label:'结算记录', icon:'fa-file-invoice-dollar', page:'settlements'}
   ]},
  {key:'system',label:'系统管理',      icon:'fa-gear',     page:'settings',
   children:[                   // 二级菜单：顶栏 hover 展开 / 收进「更多」面板时级联显示
     {label:'我的组织', icon:'fa-sitemap',          page:'org'},
     {label:'角色权限', icon:'fa-user-shield',      page:'roles'},
     {label:'菜单配置', icon:'fa-bars',             page:'menus'},
     {label:'字典配置', icon:'fa-book',             page:'dicts'},
     {label:'操作日志', icon:'fa-clock-rotate-left',page:'logs'}
   ]}
];
```
> **铁律（V2 无左栏 + 顶栏最多 8 槽位）**：`TOP_SECTIONS` 是 V2 唯一导航来源。`switchSection(sec)` 通过 `TOP_SECTIONS[sec].page` 定位首个页面并 `switchPage` 切换；顶栏 `.topnav-item` 的 `data-section` 与 `TOP_SECTIONS.key` 对应。**V2 不存在 `SIDE_NAV` / `renderSidebar` / `#navGroupBizBody`**，切勿在注入内容或文档中引用。
> **`MAX_TOPNAV=8` 与「更多」溢出**：`renderTopNav` 渲染时若 `TOP_SECTIONS.length > MAX_TOPNAV-1`（即 >7），前 7 个一级菜单渲染为平铺 `.topnav-item`，**第 8 个槽位固定为「更多」按钮**（`#topnavMore`），溢出的一级菜单进入 `#topnavMorePanel` 下拉面板。面板内每个含 `children` 的一级菜单行（`.topnav-more-row.parent-active`）在 hover 时级联展开二级菜单（`.topnav-more-sub`）。**左品牌「晋能控股」与右侧用户「管理员」用 `flex-shrink:0;white-space:nowrap` 锁定，菜单区 `flex:1;min-width:0;overflow:hidden`，永不被挤压换行。**
> **二级菜单（children）**：一级菜单可带 `children:[{label,icon,page}]`。① 平铺的一级菜单 hover 时在其下方展开 `.topnav-sub`；② 收进「更多」的一级菜单 hover 时在面板内右侧级联 `.topnav-more-sub`。两者均通过事件委托（`.bindTopNav()`）点击 → `switchSection`/`switchPage`，无需内联 `onclick`（规避 lint C1-5 误报）。
> ⛔ **业务板块多子页导航唯一范式（children 下拉，禁止 GROUPS 页内页签）**：凡含多个子页的业务板块（如服务管理=服务项目+项目分类、技师管理=技师审核+技师列表、交易管理=订单+流水+提现+结算…），**一律用 `TOP_SECTIONS` 的 `children` 二级下拉**，与系统管理同一套 UI（顶栏 hover 展开 / 「更多」面板级联）。**严禁**在业务页面内自创 `GROUPS` + `renderGroupTabs` 页内页签切换——那会制造「系统管理走顶栏下拉、业务板块走页内页签」的导航割裂（已列入踩坑库）。每个 `children.page` 必须有对应的 `.page[data-page=...]` 注入页，且都能从顶栏到达（lint 导航可达性校验）。
> **系统管理入口**：顶栏「系统管理」区段（带 5 个 `children`）切到 `#page-settings`；其二级子页 `org/roles/menus/dicts/logs` 由「更多」或 hover 级联到达。browser-check `M22`/`B3++++` 校验 `#page-settings` 激活且 `org/roles/menus/dicts/logs` 子页存在；`B3++++` 另断言顶栏槽位 `≤8`（含「更多」），超出即判失败。
> build 对 V2 **跳过** `--nav` 的 HTML 注入（V2 无左栏导航）；导航定制一律走 `navjs` 注入文件（`TOP_SECTIONS` 声明）。

### 4.2 pages（业务页面，每个 `.page` 必须有 `data-page`）

> ✅ **页面头用模板共享的 `#pageHeader` 组件（自动化，禁止手写）**：列表页/表单页顶部**不再手写** `page-header`/`h2`/`page-desc` 标题头（易重复、易单调、且会和自动页头叠加）。模板已在 `.content-scroll` 内置共享 `#pageHeader`，由 `switchPage` 从 `TOP_SECTIONS`（推导 一级/二级 面包屑，末级即 H2 标题）+ `PAGE_META`（desc 描述、actions 右侧操作）**自动填充**。注入时只需在 `PAGE_META[pageId]` 配 `desc` 与 `actions`，面包屑/描述/操作即自动出现；首页(dashboard)与详情页由 JS 隐藏，无需处理。详见 §4.2.2。
> ⛔ **状态标签必须用 `<td>` 包裹**：`tagBy(map, val)` / `tagFrom(map, key)` 返回的是 `<span class="tag">`，**必须**写成 `'<td>' + tagBy(...) + '</td>'`，禁止裸接在 `<tr>` 里（否则浏览器自动修正导致整行列错位）。

### 4.2.2 页面头 Page Header（自动推导，行业主流）
- **位置**：`.content-scroll` 顶部共享 `#pageHeader`（模板已内置），所有 `.page` 之上、唯一一份，随 `switchPage` 切换内容。
- **三要素**：

## 9. UI 细节规范（同 V2/V3，模板内置）

### 9.1 翻页器布局：共 X 条左置 / 翻页按钮右置
- 模板 `pagedRender()` 渲染的分页器（`.table-footer`）固定结构：`<div class="table-footer"><span class="pg-count">共 <b>0</b> 条</span><div class="pages" id="XxxPager"></div></div>`——左侧 `.pg-count`（「共 N 条」）+ 右侧 `.pages`（页码按钮组），`justify-content:space-between` 撑开。**禁止只写 `.pages` 容器漏掉 `.pg-count`**（renderPager 依赖其更新计数，缺失会导致计数不显示、按钮位置错乱，lint **C1-19** 拦截）。
- browser-check 断言 `.pg-count` 在 `.pages` **之前**，倒置即判失败。

### 9.2 列表布局铁律（D32/D33/D34，2026-08-13 校园集市项目固化）

桌面端 data-table 必须同时满足以下 5 条，否则视觉失衡且用户无法完整看到操作：

1. **列等宽均分**：`table.data-table` 使用 `table-layout:fixed`，未设宽度的列自动均分整个卡片宽度（禁止操作列后大量留白）。
2. **首尾 20px**：`.table-wrap{padding:0 20px}`，`thead th:first-child{padding-left:20px;text-align:left}`，`th.action-col{padding-right:20px;text-align:right}`——首字段内容距卡片左边界 20px，操作列末按钮距右边界 20px。
3. **文本列左对齐且表头/内容对齐**：`thead th` 默认 `text-align:left`；`tbody td` 也必须默认 `text-align:left`（确保每列表头与下方内容严格左对齐，不再错位）。首列 `td:first-child{text-align:left}`、操作列 `td.action-col{text-align:right}` 与对应表头对齐。
4. **操作按钮全部平铺、禁止换行**：操作列 `td.action-col{display:flex;justify-content:flex-end;flex-wrap:nowrap;gap:8px}`。**禁止**用「更多」下拉折叠按钮；不管 2/3/4 个按钮都必须在一行显示，靠 table-layout:fixed 自动分配宽度承载。
5. **头像列完整显示**：含头像的单元格（`.user-cell` 或 `td:has(.avatar-circle)`）必须 `overflow:visible`，且全局 `tbody td` 不得使用 `max-width:0`（旧模板 bug：会塌缩头像列，只显示一半）。

row 函数写法：
- 头像列：`<td class="user-cell">` + `avatarHtml(name)` + `<span class="uname">昵称</span></td>`。
- 操作列：`<td class="action-col">` + 所有按钮直接拼接 + `</td>`，**不要**包 `<div class="dropdown">` 或「更多」按钮；缺少 `action-col` 类会导致操作 `td` 也左对齐，与右对齐的表头错位。

反模式：
- `td.action-col` 写 `flex-wrap:wrap` → 按钮换行，判失败。
- 操作列出现 `.dropdown` / `.dropdown-menu` / `toggleDropdown` → 用下拉隐藏按钮，判失败。
- `tbody td{max-width:0}` → 头像只显示一半，判失败。
- `th.action-col{width:1%}` → 操作列被压窄，按钮竖排/溢出，判失败。

约束落到检查：
- `agent-lint` **C1-16 / C1-17 / C1-23 / C1-26 / C1-27** 静态拦截。
- `browser-check` **B9** 运行时断言：操作列按钮不能换行、头像不能裁剪、每列表头与内容 `text-align` 必须一致。

### 9.3 登录卡布局（全屏背景图 + 居中白卡，重构版）
- 结构：`.login-page` > `.login-bg`（`<img>` 全屏铺满）+ `.login-bg-mask`（半透明渐变遮罩）+ `.login-card`（居中白卡，毛玻璃）。

### 9.3a 登录页复用铁律（D37 强制，禁止重复产出）
